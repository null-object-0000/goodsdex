> 范围：只读线上接口与现有仓库，**不改代码、不写 `public/`、不推分支**；本轮唯一新增文件就是本文。

## 1. 结论：两级够不够

### 1.1 够，而且不需要三级

**够。** 理由不是「3,700 条不多」，而是**用户做购买决策只需要两次分类判断**：

1. 我买的是哪个生活场景（手机/电脑/厨房/清洁/出行…）——11 个一级；
2. 这个场景里具体是哪一类形态（笔记本还是平板、壁挂还是立式、扫地机还是洗地机）——102 个二级。

再往下就不是分类问题了，而是**参数和价格**：14 寸还是 16 寸、1.5 匹还是 3 匹、128G 还是 256G、500 元还是 5,000 元。这些应该用筛选 chip 和排序解决，做成第三级只会多一次点击，不会减少选择。

按线上真实数据算：

- 3,709 条可浏览商品 ÷ 102 个二级 = **平均 36.4 条/二级**；
- 8 个一级的二级数 ≤ 11，只有 3 个超过：相机与无人机 12、居家生活 16、生活电器 19；
- 最大的二级是笔记本 323、平板 227、摄影器材配件 191、手机 184、台式机 126、清洁电器配件 125。前四个需要「价格带 + 关键参数」收敛，不是继续分层。

**唯一有三级压力的是「配件」**：配件跨设备、数量大、形态杂。本方案的处理不是加第三级，而是**把配件按设备域拆成二级**：相机配件归「相机与无人机」，无人机配件归「相机与无人机」，清洁配件归「生活电器」，手机壳/膜归「手机与穿戴」，充电/线材/电池归「数码配件」。这样每个配件二级都天然带设备域，不需要「配件 → 配件类型 → 具体配件」三级。

**结论：两级；没有必须三级的例外。** 如果未来某个二级超过 300 条且内部形态差异确实大到无法用参数筛选（目前只有摄影器材配件 191 接近），再单独评估，不在本轮预设三级。

### 1.2 为什么是一级 11 个

- **能一屏扫完**：手机 3×4 网格放 11 个，剩 1 格做「全部/搜索」，不用滚动。
- **不再多**：12 个就要加「母婴与宠物」，但它只有 14 条（婴儿推车 1、宠物 5+1、益智积木 3、教育机器人配件 4），撑不起一个一级；放进「居家生活」更合理。
- **不再少**：10 个就要把「汽车与户外」并进「箱包与服饰」或「数码配件」，但汽车 17 条、户外电源 64 条是独立购买场景，硬并会让人找不到。
- **不按「数码产品类」这种词命名**：11 个名字都是用户嘴里会说的词，见 §2。

### 2.2 为什么分面条数不能直接当「这个分类有多少商品」

线上 127 个分面里，很多分类被当成了**搜索关键词标签**，不是商品主分类。收编后按主分类 + 名称规则重算，差距很大：

| 源分类 | 分面条数 | 收编后真实条数 | 差在哪 |
|---|---:|---:|---|
| 扫地机器人 | 120 | **26** | 94 条是拖布、边刷、滤芯、清洁剂、上下水装置等，不是整机 |
| 洗地机 | 98 | **12** | 大量是滚刷、滤芯、清洁液、配件套装 |
| 吸尘器 | 55 | **14** | 大量是滤芯、尘袋、拖地附件 |
| 除螨仪 | 29 | **5** | 大部分是除螨仪/吸尘器滤芯 |
| 净水器 | 118 | **50 台 + 67 条滤芯** | 滤芯被算进了净水器；分面 118 与主分类 117 差 1 条纯标签 |
| 笔记本 | 201 | **323** | Apple 的「电脑」214 条里有 122 条 MacBook，原分类没拆出来 |
| 电脑 | 214 | **0（拆成 122 / 82 / 10）** | 122 笔记本、82 台式/一体机、10 显示器；它本身不是二级 |
| 家电 | 814 | **0（按名称拆入多个二级）** | 它是泛标签，覆盖厨房、生活、个护多个域 |

这张表说明两件事：

1. **不能拿 120 条「扫地机器人」直接做横向对比**，否则首屏一半是拖布；
2. **也不能拿 201 条「笔记本」当全部**，Apple 的 MacBook 还在「电脑」里。收编后笔记本 323 条才是全量。

## 4. 迁移与兼容

### 4.1 数据模型：只加路径，不删旧字段

发布记录新增四个字段（旧字段全部保留）：

```json
{
  "category": "扫地机器人",
  "categories": ["扫地机器人", "家电", "配件"],
  "category_l1": "生活电器",
  "category_l2": "扫地机器人",
  "category_path": ["生活电器", "扫地机器人"],
  "category_confidence": 0.98,
  "category_mapping_version": "2026-10-30.1",
  "legacy": false
}
```

- `category` 继续是二级显示名，旧客户端和旧链接还能用；
- `categories[]` 继续是搜索标签，但**不再参与分类分面**；
- `category_path` 是唯一权威层级；`category_l1/l2` 是从它派生的冗余字段，便于索引；
- `legacy=true` 的记录 `category_path=null`，不进树；
- 映射表带版本号，任何调整都升版本，便于回滚和追溯。

### 4.2 旧记录怎么补 parent

**发布时补，不在查询时动态猜。** 具体三步：

1. **一次性回填**：按本文 §3 的 127 行映射，用记录的 `category` 做主键；`category` 是「家电 / 配件 / 其他配件 / 平板配件」的记录，再按名称规则拆分。回填脚本输出 `category_confidence`，低于 0.85 的进人工复核队列，**不允许自动落到「其他」**。
2. **双写期**：新采集和旧记录都写 `category_path`；查询仍走旧 `category`，新客户端可以读新字段。双写至少覆盖一个完整发布周期。
3. **发布门禁**：非 `legacy` 记录必须有且只有一个合法 `category_l2`；`category_l2` 必须在 102 个白名单里；`category_l1` 必须与 `category_l2` 的父级一致；不合法就发布失败，不静默兜底。

为什么不在查询时动态归并：

- 动态归并每次查询都要跑名称规则，慢且不可复现；
- 同一商品在不同时间可能被分到不同二级，分析视图无法对账；
- 旧记录只有 `categories[]` 时，动态归并会把 1,139 条多标签记录重复算进多个一级。

### 4.3 发布门禁与回滚

发布前必须过：

- **完整性**：3,978 = 3,709（树内）+ 269（legacy）；0 条无归属。
- **合法性**：102 个二级、11 个一级，叶子父级唯一；没有「其他」一级。
- **一致性**：`category` 与 `category_l2` 同名或存在显式别名；`categories[]` 不再影响分面。
- **可回滚**：保留上一版 `category_mapping_version` 和旧扁平 `category`；出问题一键切回旧分面，不需要回滚数据。
- **可审计**：每条低置信度记录带 `review_note`，抽样 100 条人工核对。

### 4.4 服务端 `facets` 合同

默认**绝不返回 127 个分类**。建议合同：

```json
{
  "facets": {
    "category_tree": [
      {"id": "life", "name": "生活电器", "count": 523,
       "children": [
         {"id": "robot_vacuum", "name": "扫地机器人", "count": 26},
         {"id": "washer_top", "name": "波轮洗衣机", "count": 63}
       ]}
    ]
  }
}
```

- `GET /api/goods/search?limit=0`：只返回 11 个一级 + 一级计数；`children` 可省略或只给前 6 个。
- `GET /api/goods/search?category_l1=生活电器`：只返回该一级下的二级计数，不返回别的 10 个一级的二级。
- `GET /api/goods/search?category_l2=扫地机器人`：返回叶子商品。
- `include_empty=1` 才返回 0 条叶子；默认隐藏，避免「宠物喂食机 0」这种空入口。
- 旧参数 `?category=扫地机器人` 继续可用：先按二级精确匹配，再按旧标签别名匹配。
- 计数按**去重后的商品行**算；同一商品只进一个叶子，所以一级计数 = 子叶计数之和，可直接相加。

### 4.5 旧链接兼容

- 旧 `?category=家电`：不要映射到「生活电器」一个一级就完事，而是按旧标签索引返回原来那 814 条，页头提示「这是旧分类，已拆分，请选择具体二级」。90 天后下线旧标签查询。
- 旧 `?category=电脑`：同样按旧标签返回 214 条；新分类下没有「电脑」这个二级，页头引导到笔记本/台式机/显示器。
- 旧 `?category=平板配件`：按旧标签返回 127 条，但默认排序把真正的平板配件（2 条）置顶，其余标「可能不属于此分类」。
- 所有旧链接 301/302 到新叶子时，保留 `utm` 和 `anchor` 参数，避免分享链接丢失。

## 5. 客户端交互：两个方案与取舍

### 方案 A：一级一行、二级横向 chips（手风琴/侧栏）

```
手机与穿戴  385   [手机 184] [手机保护 60] [智能手表 70] [手环 11] … 更多
电脑与平板  814   [笔记本 323] [平板 227] [台式机 126] [显示器 81] … 更多
…
```

**优点**：

- 一屏能看到多个一级，方便跨域比较（比如「买平板还是笔记本」）；
- 不用来回返回，二级 chips 直接点；
- 桌面/平板侧栏很自然，改造成本低。

**缺点**：

- 11 行 × 最多 19 个 chips，页面很长；生活电器一行就要滚；
- 小屏上 chips 触摸目标小，容易点错；
- 二级一多就像「把 127 个换成 102 个铺开」，没有真正降低选择压力。

### 方案 B：两级钻取（一级九宫格 → 二级列表）

```
[手机与穿戴] [电脑与平板] [电视与影音] [相机与无人机]
[厨房电器]   [生活电器]   [个护与健康] [居家生活]
[箱包与服饰] [数码配件]   [汽车与户外] [搜索/全部]

点「生活电器」→ 二级列表（2 列）：
壁挂空调 7   立式空调 45
中央空调 18  空调服务 7
…
```

**优点**：

- 严格两次点击，符合「想买某个东西」的路径；
- 二级列表可以用大卡片，带图、条数、价格带；
- 手机拇指操作友好，不需要横向滚动；
- 一级九宫格一屏放下 11 个，符合 §1.2。

**缺点**：

- 选了一级就看不到别的域，跨域浏览要返回；
- 多一次页面切换，回到一级会丢滚动位置（需要缓存）；
- 对「随便逛逛」不如方案 A。

### 推荐

- **手机默认方案 B**：一级 3×4 网格 → 二级 2 列列表，顶部面包屑「全部 / 生活电器」，右上角「切换一级」；
- **桌面/平板用方案 A**：左侧一级导航，右侧二级 chips + 商品；
- 两端共用同一份 `category_tree` 数据，不做两套分类逻辑；
- 方案 B 的二级列表顶部固定一个「不确定选哪个？」入口，放 §5.1 的形态选择器。

### 5.1 用户在两个二级之间犹豫怎么办（以空调为例）

在「生活电器」的二级列表顶部，把三个空调二级做成三张形态卡，而不是让用户自己猜：

```
壁挂空调 7     立式空调 45     中央空调 18
挂墙、省地     落地、风量大     吊顶、全屋
[不确定？回答 3 个问题]
```

三个问题：

1. 房间面积：≤20㎡ / 20–35㎡ / 全屋多个房间；
2. 安装条件：能打孔挂墙 / 只想落地 / 已吊顶可走管；
3. 预算：入门 / 主流 / 高端。

推荐规则（只做高亮，不自动跳转）：

- ≤20㎡ + 能打孔 → 高亮壁挂；
- 20–35㎡ + 只想落地 → 高亮立式；
- 全屋多房间 + 已吊顶 → 高亮中央；
- 不能打孔也不能吊顶 → 高亮立式，并提示「需确认外机位」。

同时给一张 3 行差异卡：

| | 壁挂 | 立式 | 中央 |
|---|---|---|---|
| 安装 | 挂墙，需打孔 | 落地，需外机位 | 吊顶，需走管 |
| 适用 | 单间 ≤20㎡ | 单间 20–35㎡ | 全屋多房间 |
| 占用 | 不占地面 | 占 0.5–1㎡ | 不占地面，占层高 |

这样用户即使点错，也能在列表顶部看到「你可能更需要立式」的提示；不强制改选。

同样的形态选择器复用到：

- 洗衣机：波轮 vs 滚筒（是否要热水/是否嵌入柜体）；
- 相机：机身 vs 运动相机 vs 无人机（拍什么/要不要防抖）；
- 笔记本：轻薄 vs 性能（重量/显卡/续航）。

## 6. 「想买某个东西」的两条入口

### 6.1 入口 A：有具体商品（电商分享链接）

流程：

1. **解析链接**：拿到平台商品标题、品牌、价格、关键参数、图片；解析失败就退到「按标题搜索」，不要直接报错。
2. **归到二级**：用标题 + 品牌 + 参数匹配 102 个叶子；置信度 ≥0.85 直接进；0.60–0.85 给 2 个候选让用户点；<0.60 退到入口 B 的分类选择。
3. **拉同叶商品**：按 `category_l2` 拉该叶全部商品，排除 legacy、无价（无价保留但置后）、以及明显不是同一形态的（例如用户买的是壁挂，不能把立式混进主列表）。
4. **收敛到 6 条首屏**：1 条锚点（用户链接的商品）+ 5 条候选，规则见 §6.4。
5. **进入统一分析视图**：`/compare?l2=<leaf>&anchor=<id>`。

关键点：

- **不是把 120 条「扫地机器人」全拉出来**，而是先按主分类拿到 26 条整机，再排除配件；如果用户链接本身就是配件，则进「清洁电器配件」叶，不混进整机。
- 链接商品如果已经在库，直接复用 `id`；不在库，用解析结果建临时锚点，标记 `external_anchor=true`，不写库。

### 6.2 入口 B：不知道买什么，只知道分类

流程：

1. **两次点击**：一级九宫格 → 二级列表；二级卡片显示条数、价格带、2 张代表图。
2. **默认给「主流带」而不是最便宜**：进入叶子后，按该叶有价商品的三分位切成入门/主流/高端，默认选主流（33–66 分位），避免首屏全是低价低配。
3. **形态选择器**：如果该一级有多个相近二级（空调、洗衣机、相机），在二级列表顶部放 §5.1 的「不确定？」卡片。
4. **进入同一个分析视图**：`/compare?l2=<leaf>`，没有 anchor，默认按「主流带 + 参数完整度」排序。

关键点：

- 二级卡片必须显示**真实条数**（用 §2.1 的收编后条数，不是分面 120）；
- 0 条的叶子默认隐藏（如宠物喂食机），避免点进去空白；
- 如果用户在两叶之间犹豫，允许「并排预览」：同时显示两个叶子的 3 个指标（条数、价格带、代表机型），但不把两叶商品混进同一个对比表。

### 6.3 两条入口必须收敛到同一个分析视图

**同一个路由、同一个组件、同一个 API 返回结构**，只差一个 `anchor` 参数：

```
/compare?l2=robot_vacuum&anchor=CN:mi_cn:product:xxx&entry=A
/compare?l2=robot_vacuum&entry=B
```

视图字段：

| 区块 | 字段 | 说明 |
|---|---|---|
| 头部 | 二级名、条数、价格区间、数据更新时间 | 条数用去重后的商品行 |
| 筛选 | 品牌、价格带、3–5 个关键参数、形态 | 每个 chip 带条数；选完即时收敛 |
| 商品卡 | 图、名称、品牌、价格、价格类型、3 个关键参数、抓取时间、来源 | 不造评分/销量 |
| 对比表 | 价格、关键参数、差异高亮、legacy 标记、无价标记 | 最多 20 条 |
| 底部 | 数据来源、缺失说明、旧款说明 | 价格 null 不隐藏原因 |

**去重规则**：先按 `id` 去重（线上有 5 行重复 id），再按 `product_id` / `gid` / 归一化名称 + 关键参数折叠同款不同色/不同容量。不能把 iPhone 的 11 个颜色当成 11 个机型来对比。

**没有的数据不要造**：当前库没有销量、评分、上市日期；排序里不允许出现「销量最高」「好评优先」「最新上市」。只能用价格、参数、`fetched_at`（数据新鲜度）和 `legacy` 状态。

### 6.4 首屏 6 条与排序规则

**入口 A（有锚点）**：

1. 硬门槛：同二级、同形态、非 legacy、价格在锚点价的 0.5×–2× 之间（锚点无价则不限价）。
2. A 档：同关键参数档（如笔记本同屏幕尺寸/同 CPU 档、空调同匹数、扫地机同基站形态）；按 `|价格 − 锚点价|` 升序，再按 `fetched_at` 降序。
3. B 档：相邻参数档；同样按价格距离升序。
4. C 档：同叶其余商品；按价格升序。
5. 首屏 6 条 = 锚点 1 + A 档 3 + B 档 1 条更低 + B 档 1 条更高；不足从 C 档补。
6. 无价商品不进首屏 6 条，但在「全部」里置后并标「暂无价」。

**入口 B（无锚点）**：

1. 先按价格三分位分入门/主流/高端；
2. 默认主流带；
3. 首屏 6 条 = 入门 2 + 主流 2 + 高端 2，保证用户看到价格跨度，而不是被最便宜锁死；
4. 带内按「参数完整度降序 → 价格升序」；参数完整度 = 该叶 3–5 个关键参数中非空的数量。

**两个入口都遵守**：

- 同一叶最多 20 条进对比表，其余用「加载更多」；
- 排序切换只有：最接近锚点（仅 A）/ 价格低到高 / 价格高到低 / 数据最新；
- 「数据最新」指 `fetched_at`，不是上市时间，UI 文案必须写「数据更新时间」；
- 价格 null 永远置后，不参与价格排序；
- 配件/耗材不混进整机叶（已通过 §2.1 的拆分解决）。

### 6.5 边界与失败

- 链接解析不到商品：不要空结果，直接展示「没识别出商品，按分类选」并进入入口 B；
- 叶子只有 1–2 条：首屏全展示，不强行凑 6 条；
- 叶子 0 条：不展示该叶，或展示「暂无商品，去相邻分类」；
- 锚点商品已下架/legacy：仍可作为锚点，但标「旧款」，对比表默认排除 legacy，用户可手动打开；
- 价格缺失：标「暂无价」，不参与「最接近」排序；
- 同款多色：折叠成一张卡，颜色作为卡片内选项，不占 6 条首屏名额。
