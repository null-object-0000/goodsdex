# 苹果官网采集侦察（2026-10-16）

## 一、结论：能采"机型 + 规格"，**采不到价格**

| 数据 | 页面 | 能不能采 |
|---|---|---|
| 机型名录 | `/iphone/compare/` | ✅ 能（含历史机型 iPhone 11 起） |
| 全套规格（20 个维度） | `/iphone/compare/` | ✅ 能：芯片 / 显示屏 / 摄像头 / 视频 / 前置 / 容量 / 尺寸重量 / 防水 / 电池 / 安全验证 / 蜂窝连接 / 感应器 / SIM / 端口 / Apple 智能 / Siri |
| **价格** | 只在**商店购买流程** | ❌ **采不到**（见下） |
| 官方折抵 / 翻新价 | `/shop/trade-in`、`/shop/refurbished` | ⏳ 商店状态相关 |

## 二、三个必须知道的坑

**① 纯 curl 拿不到，必须走浏览器**
`curl` 访问商店类页面返回 **503**，响应体是苹果的商店状态页；真浏览器打开正常。
→ 采集要实现成**浏览器驱动**（和我们抓小米商城的做法一致）。

**② 苹果商店会"闭店"——而且今天正在闭店**
`/shop/refurbished/iphone`、`/shop/trade-in` 现在返回同一句话：

> 来得早，来得好。**即将与你见面。北京时间晚 8 点接受预购。**一会儿见。

即 **苹果为预购（iPhone 18 系列）临时关闭了商店**，今晚 8 点才开。
→ 采集脚本**必须识别"闭店"状态并跳过**，否则会把闭店页当成"这个页面没有价格"。

**③ robots.txt 指向购买流程是禁止的**
```
Disallow: /*shop/browse/overlay/*
Disallow: /*shop/iphone/payments/overlay/*
Disallow: /cn/shop/buy-*
```
字面匹配的是 `/cn/shop/buy-*`；我们在 apple.com.cn 上看到的价格页是 `/shop/buy-iphone`（前缀是 `/shop/` 不是 `/cn/shop/`）。
**字面上没被这条规则匹配，但意图很清楚：购买流程不给爬。**
→ 建议：**官网只采机型与规格，价格不采**。（若要用购买页，需明确接受这个风险。）

## 三、对比页的数据结构（可复用）

```
.compare-section
  .compare-row           ← 一行规格
    .compare-rowheader   ← 规格名（芯片 / 摄像头 …）
    .compare-column      ← 每款机型一列
```
- 默认只渲染 **3 款**（iPhone Duo / 18 Pro Max / 18 Pro），其余机型在**下拉选择器**里
- 抓全需要交互下拉（或按机型逐个打开对比链接）
- 实测：20 行规格、结构稳定、无需登录

## 四、建议方案

1. **机型 + 规格** → 从对比页采（浏览器驱动、低频），建**苹果机型档案**，补上 iPhone 这块空白；
2. **价格** → **不从官网爬**。两条更稳的路：
   - **公开发布价人工维护**：iPhone 每年就几款，价格是公开新闻，维护成本几分钟；
   - 或等**京东联盟 `goods.query`** 权限下来后按型号搜。
3. **残值** → 用**转转**（已实测：`iPhone 15 Pro 256G 95新` → 成交价 ¥2,878–6,356），顺带给 iPhone 攒残值历史。
4. 采集节奏：**每天 1 次以内 + 缓存**，避开苹果商店的整点/预购窗口。
