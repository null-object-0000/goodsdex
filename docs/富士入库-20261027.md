## 稳定 id

机身为 `CN:fuji:model:<官方页面slug>`；套机追加 `-kit-<镜头slug>`，详见上表。以 URL slug 精确识别，不使用标题模糊匹配、颜色、价格、抓取时间或顺序号。`x100v` 与 `x100vi`、`x-h2` 与 `x-h2s`、`x-t30-ii` 与 `x-t30-iii` 均不同。X half 使用实际官方页面 slug `x-hf1`，与报告旧示例 `x-half` 的差异是遵从本次用户要求“官方型号slug”。不确定镜头使用明示 `unconfirmed` 的固定后缀；未来补全时需要显式维护迁移关系，不能静默改 id。

两次完整采集流程（第二次命中已落盘缓存）产生相同的 24 个 id，第二次网络请求增量为 0。测试还覆盖同代不同款、机身/套机、13 种套机 id 唯一性及发布幂等性。

## 采集纪律、断点与失败

串行并发 1，同一 host 请求开始时间最短间隔：主站 2.150058 秒、图片 CDN 2.150098 秒、京东 2.150064 秒。中国目录 host 本轮仅一次请求。请求日志共 40 个尝试，39 个实际 HTTP 响应全部 200；另一个尝试在本地 urllib 不支持环境的 SOCKS 代理协议时失败，未向目标站发出 HTTP。改用支持已配置代理的 curl 后继续，保留原错误。没有切换出口、挑战处理或反爬绕过。

本轮无 403、429、412 或 Cloudflare 挑战；总尝试 40≤300。脚本禁用自动跟随重定向（逐跳计数限速），403/429/412、挑战页、登录或 risk_handler 跳转会立即写 STOP.json 并终止，后续运行也不自动重试。缓存按 URL 哈希落盘；每条记录立即原子写入（比每 10 条更频繁），请求前后均记录日志；同输出目录由文件锁防止并行采集。

开发时另发现：X-T30 III 主图为 WebP，初始校验只接受 JPEG/PNG 而本地停止；补充 RIFF/WEBP 魔数校验后命中已下载缓存。X-S20 版本名含空格，使用 NFKC 和空白归一核对，未改镜头事实。未知参数标签、规格数量异常、版本矩阵变化等均停止，不凑数。

## 复跑和验证

运行依赖 Python 3.10+、curl；测试依赖 pytest。

```bash

# 中断时重跑相同命令，复用缓存；出现 STOP.json 时不得自动重试
# 新一轮现场刷新使用新的 --out，保留旧轮日志，禁止以此逃避已记录的站点拦截
python3 scripts/fuji_catalog.py publish --out data/fuji --data-tree /path/to/checked-out-data
uv run --with pytest python -m pytest -q tests/test_fuji_catalog.py tests/test_publish.py tests/test_identity.py
```
