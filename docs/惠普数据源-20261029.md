# 惠普（HP）台式机 / 笔记本：公开数据源摸底

> 只读核查。没有改 `public/goods.json`、没有改采集脚本、没有推分支；本文是唯一新增文件。
>
> 现场抽样：2026-10-29 15:5x–16:1x（+08:00）。全部用 `curl`，未带 cookie / token / 登录态；同一 host 请求间隔按 2.2 秒控制。
>
> 范围只覆盖**惠普台式机（含整机、主机、一体机）**与**惠普笔记本（含轻薄本 / 游戏本 / 工作站）**。打印机、显示器、耗材、服务器未采。

## 结论先说

1. **能稳定采，而且能到配置级。** 中国惠普官方商城不是 `store.hp.com.cn`，是 **`www.hpstore.cn`**；`store.hp.com.cn` 在本机 DNS 直接 NXDOMAIN，`store.hp.com` TLS 连接被断开。`www.hpstore.cn` 的类目页和商品页都是服务端渲染，不带 cookie 直接 200，商品页有完整规格表、价格、图片。
2. **粒度是「一个 product number 一个 SKU 一个页面」，不是型号级。** 商城没有 CPU / 内存 / 硬盘硬件配置器；同类目名下的不同配置是不同 product number、不同 PDP。抽样的 5 个 PDP 的 `productType` 都是 `simple`。
3. **唯一标识用 HP product number（如 `DC0F0PA`），不是 Magento 内部 `productId`。** product number 同时是页面 `sku`、`topLevelSku`、URL 后缀；同一市场名可以对应多个型号代码和多个 product number，例如「星Book Pro Air 14」的 `DK8G8PA`（Ultra 5 / 512G / ¥6499）与 `E6EA7PA`（Ultra 7 / 1T / ¥8499）。
4. **字段覆盖足够做商品库：** 整机图、屏幕、CPU、内存、硬盘、显卡、重量、尺寸、接口、电池、保修、商城售价、库存状态都能拿到。**拿不到的是：真实上市时间、EAN/GTIN、有明确语义的官方指导价（MSRP）**。
5. **在售体量：笔记本 173 条 + 台式机/一体机 44 条 = 217 条 SKU。** 这是类目工具栏给出的商品数，不是估算；笔记本 12 页（每页 15，最后一页 8），台式机 3 页（最后一页 14）。
6. **没有可用的公开 JSON 商品接口。** Magento GraphQL 返回 403，REST `/rest/V1/products/...` 返回 401「consumer isn't authorized」；但 PDP 的 `setProduct({...})` 内嵌 JSON、规格表 `<dt>/<dd>`、类目页的 `Product` JSON-LD 已经够用，**正常商品浏览不需要浏览器**。
7. **必须用浏览器的是 HP 支持站目录页**：`support.hp.com/cn-zh/products` 只有 7 KB，`<app-root></app-root>` 为空，正文 0 行；停售/旧款规格要走这条路的话，得带 JS 渲染，而且没有价格。

## 2. 数据粒度：配置级，不是型号级

### 2.1 证据

- 类目页 173 / 44 条，每张商品卡一个 product number。
- 5 个抽样 PDP 的 `productType` 全部是 `simple`，不是 `configurable`。

### 4.1 「上市时间」的准确说法

能拿到的是 Magento 的目录时间，不是厂商发布日：

```text
DC0F0PA: createdAt 2026-04-16 03:30:35, newFromDate 2026-09-17 13:00:22
DK8G8PA: createdAt 2026-04-23 05:16:58, newFromDate 2026-10-21 11:19:07
E6EA7PA: createdAt 2026-09-17 04:26:53, newFromDate 2026-10-21 11:22:09
D53W6PA: createdAt 2026-03-31 08:13:51, newFromDate 2026-10-14 11:50:08
D3SE7PC: createdAt 2026-06-06 06:40:30, newFromDate 2026-08-27 11:04:29
```

如果商品库需要「上市时间」，建议字段名写 `catalog_created_at`，不要写 `launch_date`；真实 `launch_date` 标空。

### 4.2 「价格」的准确说法

- `pricing.regularPrice` 和 `finalPrice` 都是 **当前商城售价**，不是 MSRP。
- `price-suggest` 是页面上的建议价（class 名如此），但 HTML 里只有 class 名，没有可见的「建议零售价」标签。
- 所以：
  - `price` = 当前售价，✅
  - `list_price_displayed` = `price-suggest` 数值，⚠️
  - `msrp` = ❌，不要用 `price-suggest` 冒充。

## 6. 反例与风险

### 6.1 纯前端渲染，必须浏览器

| 页面 | 现象 | 影响 |
|---|---|---|
| `support.hp.com/cn-zh/products` | 7,087 字节，`<app-root></app-root>` 空，正文 `[]` | 停售 / 旧款规格要带 JS；没有价格 |
| `www.hpstore.cn` 购物车 / 结算 | 需要 Magento session / JS | 本轮不涉及；浏览商品不需要 |
| `www.hp.com/cn-zh` 导航抽屉 | 导航交互是 JS | 页面正文是 SSR，不影响抽系列页文案 |

**不需要浏览器**：`www.hpstore.cn` 类目页、PDP、站内搜索结果页都是服务端渲染，HTML 里直接有商品卡 / 规格 / 价格。

### 6.2 接口的权限边界（不是签名问题）

- GraphQL：403 Forbidden。
- REST：401，`Magento_Catalog::products` 资源未授权。
- 页面里的 `form_key` 是表单 CSRF，不是目录接口的签名参数。

**没有发现**需要签名 / 加密参数的公开目录接口；也没有去猜。

### 6.3 PDP 的 `Product` JSON-LD 不可靠

- 类目页：每个商品卡有 `Product` JSON-LD，可用。
- PDP：抽样的 5 个页面里 **5/5 都没有 `Product` JSON-LD**，只有 `BreadcrumbList` 和（部分有）`VideoObject`：

```text
pages/pdp-dc0f0pa.html:  1×BreadcrumbList, 1×VideoObject
pages/pdp-d53w6pa.html:  1×BreadcrumbList, 1×VideoObject
pages/pdp-d3se7pc.html:  1×BreadcrumbList, 1×VideoObject
pages/pdp-dk8g8pa.html:  1×BreadcrumbList, 1×VideoObject
pages/pdp-e6ea7pa.html:  1×BreadcrumbList
```
- 所以 PDP 的 SKU / 价格 / 规格不要等 JSON-LD，直接读：
  1. `magentoStorefrontEvents.context.setProduct({...})`
  2. `<dt><h3 class="label">…</h3></dt><dd><h4 class="value">…</h4></dd>`
  3. `data-price-amount` / `price-suggest`

### 6.4 「选择配置 (21)」是配件推荐，不是配置器

见 2.3。会把鼠标 / 电源 / 包算进笔记本体量。

### 6.5 站内搜索没有结构化数据、没有总数

- 搜索页有商品卡，`data-sku` 可解析，但没有 `Product` JSON-LD，也没有「共 N 件」。
- 只能拿来做「用户输入型号 → 找 SKU」的辅助，不要用它算体量。

### 6.6 sitemap 是筛选页大全

- 72,070 条 URL，70,688 条带 query。
- 1,046 个 PDP-like slug 里混着配件 / 旧款；和 173 / 44 对不上。
- 不要用它枚举在售商品。

### 6.7 robots 只点名了两个爬虫

```text
User-agent: Baiduspider-render
Disallow: /
User-agent: Googlebot
Disallow: /
Sitemap: https://www.hpstore.cn/sitemap.xml
```

- 没有 `*` 组；但这只是技术事实，不是授权。正式采集前仍要看网站条款。
- 本站是腾讯 EdgeOne，响应头没有 `x-ratelimit`；本轮 2.2 秒间隔、28 次请求没有 429 / 验证码。
- **频率限制的具体阈值没有测出来**；不要因为本轮没被限就并发。建议单线程 ≥2.1 秒，按 217 条分批。

### 6.8 数据质量坑

- `D3SE7PC` 型号代码是 `Not Applicable`。
- 价格会变；`price-suggest` 语义不明。
- `createdAt` 不是上市时间。

- 中国商城：`www.hpstore.cn`。

## 7. 推荐路径

### 7.1 主路径（推荐）

**第一步：枚举 SKU**

```text
笔记本：GET https://www.hpstore.cn/laptops-tablets.html?p=1 .. 12
台式机：GET https://www.hpstore.cn/desktops.html?p=1 .. 3
```

解析：

- 优先 `script[type="application/ld+json"]` 里 `@type=Product` 的块：`sku`、`name`、`image`、`offers.price`、`offers.availability`。
- `data-sku` / 商品卡 `href` 做兜底（防止某张卡没有 JSON-LD）。
- 按 `sku` 去重；用工具栏总数校验：笔记本 173、台式机 44。

**第二步：抓 PDP**

PDP 数 = 217（如果在售全量）。每条解析：

- `magentoStorefrontEvents.context.setProduct({...})` → `sku`、`name`、`pricing.regularPrice`、`createdAt`、`canonicalUrl`、`mainImageUrl`、`productType`。
- 规格表 `<dt>/<dd>` → CPU、内存、硬盘、显卡、屏幕、重量、尺寸、接口、电池、保修。
- `price-suggest` → 页面建议价 / 节省额（单独字段，不要叫 MSRP）。
- `class="stock …"` → 库存状态。
- 图片：`mainImageUrl` + 页面画廊的 `media.hpstore.cn` 链接。

**第三步：归一**

建议字段：

```text
id                 = sku（product number）
model_name         = 名称去掉颜色/配置后的市场名
model_code         = 名称里的 ap1025AX / ku0033TU 等（可空）
product_type       = 笔记本 / 台式机 / 一体机
cpu / ram / ssd / gpu / screen / weight / dimensions / ports / battery / warranty
price              = 当前商城售价
price_suggest      = 页面建议价（可选）
currency           = CNY
availability       = InStock / 其他
catalog_created_at = createdAt（不是上市时间）
image_urls         = []
source_url         = canonicalUrl
fetched_at         = 抓取时间
```

**第四步：频率**

- 同一 host 单线程 ≥2.1 秒；217 条 PDP 约 8 分钟，可接受。
- 先抓类目页，再按 `sku` 增量抓 PDP；已抓过的按 `updatedAt` / 价格变化决定是否重抓。
- 不要并发、不要跑 `product_list_limit=all`（无效）。

### 7.2 如果官网拿不到，退到哪个源

按优先级：

1. **`www.hpstore.cn` 站内搜索**：`/catalogsearch/result/?q=<型号>`，解析 `data-sku`。适合用户只给市场名、不知道 product number 的场景；没有总数，不适合全量。
2. **`www.hp.com/cn-zh` 系列页**：只补系列营销名、卖点、系列图；**不要指望它给 SKU / 价格 / 规格**。
3. **`support.hp.com` 产品档案**：按 product number 查停售 / 旧款规格；需要浏览器（当前目录页是空 `<app-root>`），没有价格、没有库存，只能做「规格兜底」。
4. **用户手动输入 product number**：如果用户在机器底部 / 包装盒上能找到 `DC0F0PA` 这类编号，直接按 product number 查；这是最可靠的「我家那台」入口。
5. **第三方（京东 / 天猫官方旗舰店）**：本轮**没有抽样**，不能写结论。如果官网确实拿不到，再单独做一轮第三方源核验；不要直接把第三方字段混进官方源。

## 8. 停售款 / 二手：要不要覆盖

这是判断题，不替你拍板。先把三个选项摊开：

| 方案 | 覆盖 | 价格 | 成本 | 风险 |
|---|---|---|---|---|
| A. 只做在售 217 | 现在买得到的 | 有 | 低 | 家里的旧 HP 录不进去 |
| B. 在售 217 + 用户手动 product number | 在售 + 用户自己的旧机 | 旧机无价 | 中 | 需要用户找编号；旧机规格靠 support 档案 |
| C. 在售 + support 档案全量 | 在售 + 大部分停售 | 旧机无价 | 高 | 纯前端、型号命名脏、无库存、噪音大 |

我的倾向（供你决定）：

- **先做 B**：在售 217 条保证价格 / 库存 / 图片准确；用户家里的旧 HP 用 product number 手动补，补不到就标 `unknown`，不猜。
- **C 不要现在做**：support 目录页是空 `<app-root>`，要带浏览器；而且没有价格，混进主库会污染「在售」口径。
- 如果以后要做二手 / 停售，单独一张表，加 `condition=discontinued/used`，**不要和 217 条在售混在一个价格/库存字段里**。
