## 复现和修复

在仓库根挂载 data 分支为 `_data`，先复制原始 `goods.json` 到 `/tmp/goodsdex-deletion-debug/goods-before.json`，保持与 runner 的 3,978 行 previous 一致。使用当前默认 supplements，先回放价格发布，再直接调用真实 Apple publisher 读取 data 的历史缓存。此回放隔离价格网络变化，不模拟或重新制造 macOS 行。

```bash
git worktree add --detach _data origin/data
cp _data/public/goods.json /tmp/goodsdex-deletion-debug/goods-before.json
PYTHONPATH=src python3 scripts/ci_refresh_prices.py \
  --public _data/public --supplements data/supplements/goods-supplements.json --offline
# 此时原版 verify 通过，current=checked=3968
PYTHONPATH=src python3 -c 'from goodsdex.apple import publish_apple; print(publish_apple("_data/data/categories", "_data/public"))'
# 输出 count=644,total=3972，此时原版 verify 抛出相同 ValueError
PYTHONPATH=src python3 scripts/verify_goods_release.py \
  --public _data/public --previous /tmp/goodsdex-deletion-debug/goods-before.json
```

失败 runner 未上传最终 goods.json，因此不声称下载了该文件：上表的 Refresh prices / Apple / verify 条数来自真实日志，四个具体差异 ID 来自相同 data 缓存和同一个 publisher 的本地重放。完整网络流水线由本次真实发布运行验证。

修复提交 `e2cf215`：

- 最终门禁读取 current 后，先调用同一个 `remove_reviewed_non_goods()`，仅过滤已批准的 10 个精确 ID。
- 用 ID 多重集合比较 merge 与 current，补充行、previous 保留行及重复次数的差异仍阻断发布；报错附带被恢复的 ID。
- 汽车保留校验、merge 的旧 ID 丢失校验、空壳校验、audit 算术及后续 publisher 减量检查全部保留。全部校验通过后才将删除结果写回 goods.json，再生成最终 meta 和 verification。
- 没有修改 supplements、release_policy 或 Apple/HP 发布逻辑；最终门禁负责在所有品牌 publisher 之后统一执行删除政策。
