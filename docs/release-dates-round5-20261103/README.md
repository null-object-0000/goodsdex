## 数据契约、显示及回滚

本轮全部候选独立在 [data/llm/release-dates.json](../../data/llm/release-dates.json)，没有修改 official 文件。原始模型自报 confidence 只留在响应；公开 confidence 由逐品牌门禁决定。本轮全部禁用，因此没有四品牌新增 LLM `release`。官方/第三方已审核日期永远优先，LLM 不覆盖。未知日期不写入 params。

既有40条 Apple LLM保留 date/source/evidence，并统一为 `usage=reference`、`internal_only=true`、`display_allowed=false`、`estimate_notice=按型号世代估算`；旧抽检100%对应confidence=high，**high也不等于可以显示成发售事实**。独立文件整批关停：

```bash
python3 scripts/disable_llm_release.py
# 再执行正常 finalize 和 refresh-release-dates 发布，才会影响线上。
```

该开关只剔除本轮文件管理的 LLM 日期，官方数据与旧轮候选不变。当前本轮新增为0，开关可幂等执行。保留 managed_ids 后即使删空 candidates 或关闭 enabled，也能清除上次导入的本轮 LLM；不要直接删除管理文件后假定旧发布数据会自行清掉。

当前数据里的日期用途：

- official/third_party 实际 availability 共 **378条**：允许标“发售时间”。
- announcement 共 **245条**：允许标“发布时间”，不是开售。
- official planned_availability 共 **31条**：只能标“预计发售（官方计划）”。
- 旧 LLM **40条**：不显示年月，不显示为发售时间，只用于新旧关系/换新路线，结果说明“按型号世代估算”。
- 仍缺 **3274行**（小米2136、大疆676、惠普218、富士49、Apple181、比亚迪14）：不推断月份、不补虚假标签。

小程序 `spend-good` 当前工作区已接入：保留release完整来源；换新卡、比较表、原始依据页均不显示LLM年月；内部排序仍可用，结果提示估算。模块/保留字段/回归测试提交 **41f97f1**。换新引擎与页面原本为用户未提交的新文件，本轮只应用必要改动，没有把整份在途工作纳入提交；本轮增量另存 [client-in-progress.patch](client-in-progress.patch)。**没有上传或发布新的微信体验版/正式版，不声称线上客户端已更新。** 当前线上客户端是否带此规则仍不能据本次API发布推定。
