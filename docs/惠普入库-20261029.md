## 字段覆盖与图片

配置级身份 217/217（100%）；CPU、内存、硬盘、显卡字段 217/217 非空。显卡字段保留源的粒度：CTO 两条只写“集显”，部分普通 SKU 也只写“英特尔显卡”等，不能据此声称 217 条都有精确 GPU 芯片型号。

| CPU、内存、硬盘、显卡 | 217/217 | 保留源值，不从 CPU 反推 GPU |

## 刷新与发布

采集入口 `scripts/crawl_hp.py`，独立可运行；`--dry-run` 只输出，不写产物；`--replay` 校验保存的 HTML 响应 SHA-256 后重解析，已有图片复用此前的 GET 校验。只在现有 crawl-all 每日任务（北京时间 03:37）采集惠普，没有加入小时采集。成功档案累积，失败/列表缺席不删除旧 SKU、不推断停售。所有 HTTP 请求按 host 串行，前一请求完成后等待≥2.1秒。

```bash
python3 -m pip install Pillow
python3 scripts/crawl_hp.py --dry-run --limit 1
python3 scripts/crawl_hp.py --out data/hp --public /path/to/data/public
PYTHONPATH=src python3 scripts/verify_goods_release.py --public /path/to/data/public --previous /tmp/goods-before.json
python3 scripts/finalize_public.py --public /path/to/data/public --previous /tmp/goods-before.json
```

发布沿用生成→字段归一→去重→分片→data 分支→OSS 镜像。原 `supplements.merge()` 已有“上一版 ID 本版缺失即失败”，现在又在最终分片前增加同一守卫，所有发布工作流都传 previous。日常非惠普发布保留上一版惠普行；新增品牌不依赖人工补充表。此次以原始列表相等断言证明既有 3,613 行全部不变。

## 与 dsh 调研的统一结论

已逐项对齐 [dsh 原始调研](惠普数据源-20261029.md)，本节为全量验证后的实现口径。

| 项目 | dsh 抽样结论 | 全量验证后的处理 |
|---|---|---|
| 主源/ID | hpstore.cn SSR，product number，不用内部 productId | 一致；217 条逐一核对 SKU |
| 体量 | 类目卡 173+44=217，尚未抓全 | 一致；217 个唯一 SKU、57 个型号组 |
| CTO | 2 个 CTO 是否多配置尚未验证 | 实测两页 setProduct.productType=simple，标题各自是固定 I5/I7+16G+512G+集显；只收这两个明确配置 |
| 字段“能拿到” | 5 个 PDP 的字段并集，不保证每条齐 | 重量仅141、屏幕实际尺寸176；缺失/不适用置null。1条硬盘从同页“内存和存储”概览取得，2条CTO从明确标题取得 |
| 图片 | 有原图/画廊链接，未逐图验收 | 新增逐图GET门槛；700px原图拒绝，画廊替代后217条有合格图 |
| 售价/MSRP/上市时间 | 当前售价可用；price-suggest不等于MSRP；目录时间不等于上市 | 完全一致，store_sale/null/null |
| 支持站 | 目录是SPA；部分详情可能SSR，未排除 | 官方搜索可见旧款规格文档，但本机直接GET样本c06451028为403；未绕过，不把全部支持站说成不可用 |
| 旧款范围 | 在售217不等于历史全量，建议按用户product number补 | 本次不声称历史穷举，也不替用户决定以后是否做全量。旧星14 Pro、光影精灵等未被这217条覆盖的具体SKU仍是明确缺口；没有将“没搜到”写成“不存在” |
