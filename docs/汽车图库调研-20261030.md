## 0. 结论先行

1. **汽车之家能精确定位到这台车，但图库里没有时光灰。** `spec=56153` 的页面标题就是“汉 2022款 DM-i 121KM 尊贵型”，但该配置的“外观”图只有 **7 张，全部是玄空黑**（`colorid=7685`）；`时光灰`（`colorid=7686`）在该配置下的图片数是 **0**；“官图”分类也是 **0 张**。
2. **太平洋汽车也能精确定位到这台车，但抽样看到的同样是玄空黑。** `m112979` 就是“汉 2022款 DM-i 121km 尊贵型”，外观实拍 40 张；抽第 1–8 张和第 40/40 张，均为玄空黑，且都带“太平洋汽车”车牌/角标水印。
3. **懂车帝在本轮拿不到。** 车型页、参数页、品牌页最终都落到 `/login-required`；不登录就没有可复核的图库入口。公开的 `car_list` JSON 接口存在，但需要车系 ID，而发现车系 ID 的页面被登录拦截；本轮没有取得汉的可用车系 ID。
4. **因此，“2022 款 + 121KM 尊贵型 + 时光灰”三者全对的公开图库图：拿不到。** 能对上年款和配置的图有，但颜色是玄空黑；颜色对得上的 2022 图只有汉 EV 创世版（56542/56566/56451），前脸不是 DM-i，不能拿来充数。
5. **建议不要用黑车图冒充时光灰。** 这台车的主图优先走车主上传（`user_upload`）；没有车主图就保持 `image=null`、`image_status=official_unavailable`，前端显示“官方图待补”。如果业务上必须放一张占位图，只能用汽车之家 56153 的前 45° 图，并显式标注“同款同配置，颜色为玄空黑，非车主时光灰；来源：汽车之家”。

## 4. 懂车帝（dongchedi.com）

### 4.1 入口与拦截

本轮没有拿到可用的汉图库入口，原因不是“没有图”，而是**公开页面被登录拦截**：

| 请求 | 实取 |
|---|---|
| `https://www.dongchedi.com/auto/series/5952` | HTTP 200，4,999 B，但最终 URL 是 `https://www.dongchedi.com/login-required?redirect=%2Fauto%2Fseries%2F5952` |
| `https://www.dongchedi.com/auto/params-carIds-72691` | HTTP 200，5,007 B，最终落到 `/login-required?redirect=%2Fauto%2Fparams-carIds-72691` |
| `https://www.dongchedi.com/auto/library-brand/16`（比亚迪品牌页） | HTTP 200，5,006 B，最终落到 `/login-required?redirect=%2Fauto%2Flibrary-brand%2F16` |
| `https://m.dongchedi.com/search?keyword=%E6%B1%89DM-i` | 302，最终落到 `https://m.dongchedi.com/download/login/?callback_url=...` |

页面的 chunk 名直接是 `pages/login-required-*.js`，不是内容页；带 cookie 也一样。按“不登录”的硬规矩，到此为止。

### 4.2 公开 JSON 接口的情况

`https://www.dongchedi.com/motor/pc/car/series/car_list?series_id=5358&city_name=%E5%8C%97%E4%BA%AC` 返回 200、1,229 B JSON，说明这个接口存在且不需要登录；但 5358 对应的是“2026款-LYRIQ V”，不是汉。要查汉，必须先拿到汉的 `series_id`，而车系页/品牌页都被登录拦截；本轮没有用猜 ID 或枚举的方式绕过。

因此：**懂车帝本轮没有候选图，不能给出真实图片 URL、状态码、尺寸、水印。** 这是“拿不到”，不是“已确认懂车帝没有这张图”。

### 4.3 判定

- 图库入口：未取得可用公开入口（车型/参数/品牌页均 login-required）。
- 筛选能力：无法验证。
- 候选图：0。
- 结论：**不登录拿不到；按硬规矩放弃。**

## 6. 版权与标注建议

### 6.1 实务风险（不是法务意见）

- 这类图不是比亚迪官方图。汽车之家/太平洋汽车给图加了水印，说明站点主张权利；图的原始著作权通常在拍摄者/经销商/供稿媒体，站点通过供稿或授权取得展示权。
- 把图转载到商业小程序当商品图，属于**商业性信息网络传播 + 商业使用**；没有书面授权就有侵权风险。保留水印不代表可以商用，只代表“没有去掉权利标识”；去掉水印再商用，过错更重。
- 实务判断：
  - 被起诉的概率：对小体量商品页不算高；
  - 被投诉下架、被平台要求补授权、被竞对举报的概率：**不低**，尤其汽车之家/太平洋汽车都有版权投诉渠道；
  - 一旦收到通知，应立即下架并留痕，不要继续用。
- 如果只是内部比对、人工看、不入库、不上线，风险低；**一旦作为商品主图对外展示，建议先拿书面授权，或换车主图。**
- 不要做的事：裁掉“汽车之家/太平洋汽车”水印后当自有图；把玄空黑调色成时光灰；把 EV 图当 DM-i。

### 6.2 `image_source` 的建议取值

先对齐仓库现状，避免把两个字段混用：

- `data/supplement-20261027/public-before.json` 里的 `image_source` 实际存的是**图片 URL**（例：`"image_source": "https://cdn.cnbj1.fds.api.mi-img.com/...png"`）。
- 类型字段叫 `image_source_type`。`scripts/publish_cars.py` 对 2022 历史记录的校验是：**`image is not None` 时 `image_source_type` 必须等于 `official`**，否则拒绝发布。脚本里另有一套 `source_type` 取值（`official` / `official_news` / `miit` / `third_party`），那是“记录来源类型”，不要和图片字段混用。

所以建议分两种口径写：

| 场景 | `image_source` | `image_source_type` | 说明 |
|---|---|---|---|
| 官方当前款图 | 官方 CDN URL | `official` | 现有逻辑可用 |
| 汽车之家图（仅参考，不上架） | 图片 CDN URL | `third_party` | 不进商品主图 |
| 汽车之家图（若将来策略允许上架） | 图片 CDN URL | `third_party` | 建议同时记录 `image_source_name=autohome`、`image_source_page=...`、`image_license=unknown`、`image_color_match=false`；这些字段若尚不存在，应作为新增元数据提案，不要硬塞进现有字段 |
| 太平洋图（若用） | 图片 CDN URL | `third_party` | `image_source_name=pcauto` |
| 懂车帝图 | 本轮无 | — | — |
| 车主图 | 用户提供的文件/URL | `user_upload` | 需用户授权 |

如果你们的产品结构里 `image_source` 确实是枚举，而不是 URL，那么建议值就是：

```text
autohome / pcauto / dongchedi
```

但**当前仓库不是这个用法**：`image_source` 是 URL，`image_source_type` 才是类型。落地时不要只写一个 `autohome` 到 URL 字段里。

### 6.3 界面是否要显示“图片来源：汽车之家”

**要显示，而且要说清“非官方、颜色不符”。** 建议文案：

```text
图片来源：汽车之家（第三方图库，非官方）
图为同款同配置（2022款 DM-i 121KM 尊贵型），颜色为玄空黑，非车主时光灰
```

如果只是内部参考、不上线，则不需要 UI 标注；但一旦上线，必须有可见来源和“非官方/颜色不符”提示。只写“图片来源：汽车之家”不够，会让用户以为这是这台时光灰车的实拍。

### 6.4 与现有发布门禁的冲突

这是本轮最重要的落地约束：

- `scripts/publish_cars.py` 对 2022 历史记录的要求是“**图片要么为空，要么 `image_source_type=official`**”。
- 汽车之家/太平洋汽车的图都是 `third_party`，**按现有门禁不能写进这条历史记录**。
- 同理，`user_upload` 也不是 `official`；现有门禁同样会拒绝。要用车主图，必须先把历史记录的图片策略改成允许 `user_upload`（并保留授权证据），或把车主图放到不经过该门禁的展示字段。
- 因此本轮即使找到了图，也不应该改库；要用第三方图/车主图，必须先改发布策略/门禁（不在本任务范围），或者只把图放在文档/运营素材里，不进 `image` 字段。

## 7. 自动化可行性

### 7.1 汽车之家：可做，但是“解析页面内 JSON”，不是公开 API

步骤：

1. 车系 ID 已知（汉 = 5499）。从 `https://www.autohome.com.cn/5499/sale.html`（GBK）解析停售车型表，拿到“2022款 + 配置名 → specid”；或从 `config/series/5499.html` 的 `bag`/`color` 变量拿 spec 列表。
2. 请求 `https://www.autohome.com.cn/cars/imglist-75-x-{seriesId}-{specId}-1-0-0-x-x-1.html`。
3. 从 HTML 的 `<script id="__NEXT_DATA__" type="application/json">` 取 JSON：
   - `props.pageProps.SpecPicList.speclist[].piclist[]` → `picpath`、`colorid`、`picid`；
   - `props.pageProps.colorList.color[]` / `othercolor[]` → 颜色计数；
   - `props.pageProps.typeList` → 外观/内饰/官图等分类。
4. 颜色筛选：同一 URL 把第 6 段换成 `colorId`，例如 `...-1-7686-0-x-x-1.html`；若目标颜色 `piccount=0`，直接停止，不要回退到别的颜色。
5. 下载 `picpath` 时必须带 `Referer: https://car.autohome.com.cn/`；否则伪造 Referer 会 403。

请求约束：

- UA：常规桌面 Chrome UA 即可；不需要 cookie、不需要登录。
- 间隔：同 host ≥2.1 秒；本轮 2.2 秒未触发限制，但不要高并发。
- 稳定性：依赖 Next.js 的 `__NEXT_DATA__` 结构；站点改版会断。不是官方承诺的 API，不能当长期合同。

### 7.2 太平洋汽车：能做但不稳，不建议

步骤：

1. 从车型页 `https://price.pcauto.com.cn/m{modelId}/` 取 cookie（先访问 `https://www.pcauto.com.cn/`）。
2. 请求 `https://price.pcauto.com.cn/cars/m{modelId}-o2/` 拿实拍列表；外观大图是 `/image/sg{seriesId}-m{modelId}-wg-0-{n}.html`，**一页一张**。
3. 从每页的 Nuxt 数据里取 `pageResult[].path`；一页只稳定带当前图附近 7 条，要 40 张就得翻 40 页。
4. 没有颜色筛选参数；颜色只能靠图或页面文案人工判断。

问题：

- 不带 cookie 直接 503；
- 2.2 秒间隔仍会 503（第 20/30 页实测）；
- 40 页翻页成本高、失败重试多；
- 分辨率只有 1600×1200，水印比汽车之家重。

结论：**只适合人工补图，不适合做稳定自动化。**

### 7.3 懂车帝：不登录不可做

- 车型/参数/品牌页全部 `login-required`；
- `car_list` JSON 可用，但需要 `series_id`，发现入口被登录拦截；
- 没有找到公开的图片列表接口；本轮不尝试登录、不绕验证码。

结论：**按当前硬规矩，懂车帝自动化不可行。**

### 7.4 成本对比

以下是工程量级判断，不是报价：

| 方案 | 一次性成本 | 持续成本 | 覆盖 | 主要风险 |
|---|---|---|---|---|
| 只为这一台车手工补一张 | 1–2 小时 | 0 | 只能拿到玄空黑，仍不满足时光灰 | 低 |
| 只做汽车之家“按 spec 取图” | 2–3 人日 | 0.5 人日/月 | 年款 + 配置可覆盖，颜色不保证 | 中：Next.js 改版、Referer 策略 |
| 三站通用 | 7–10 人日 | 1–2 人日/月 | 实际只有两站可用；懂车帝登录不可用 | 高：反爬、503、版权 |
| 官方/厂商授权图库 | 商务谈判 | 授权费/续约 | 最稳，可拿官方图 | 时间/成本 |

**只为这一台车手工补一张 vs 做通用能力，成本差约 10–20 倍（只做汽车之家）到 30–50 倍（三站）。** 但本轮的关键不是成本，而是：**手工补一张也补不到时光灰**。所以“先做哪个”的答案是：**先不要做通用能力；先向车主拿一张自己车的照片。**

### 7.5 建议

- 如果只是解决这一台车：**不要写采集脚本**；人工拿图也拿不到目标颜色，直接走车主上传。
- 如果将来要做“按年款+配置取图”的内部证据工具：**只做汽车之家**，按 spec 抓 `__NEXT_DATA__`，把颜色计数当硬门槛（目标颜色 0 就报“无图”），不要回退到其它颜色。
- 不要把抓取结果直接当商品主图；先过版权/标注/门禁。

## 8. 如果全都拿不到：替代方案

### 8.1 首选：车主自己拍照上传

- `image_source_type=user_upload`（若当前枚举未定义，需新增；也可按你们现有的 `image_source=user_upload` 口径）
- UI：“图片来源：车主提供”
- 优点：颜色、配置、车况都是真的；无第三方版权风险。
- 要求：用户授权；照片里不要有车牌/人脸等个人信息，或做遮挡。

### 8.2 次选：保持无图，前端显示“官方图待补”

- `image=null`
- `image_status=official_unavailable`
- UI：“官方图待补 / 车主图待上传”
- 这是最诚实的做法，不会误导用户以为黑车就是时光灰。

### 8.3 如果业务必须放一张占位图

只能用汽车之家 56153 的 A1（前 45°）并加显式标注：

```text
图片来源：汽车之家（第三方图库，非官方）
图为同款同配置（2022款 DM-i 121KM 尊贵型），颜色为玄空黑，非车主时光灰
```

并且：

- 保留水印，不要裁；
- 不写成“官方图”；
- 不写成“时光灰实拍”；
- 收到版权通知立即下架。

### 8.4 2022 汉家族发布报道图：也不能解决颜色

本轮复核了中国金融信息网 2022-04-10 上市报道（`https://www.cnfin.com/jgdt-lb/detail/20220410/3579135_1.html`，本轮实取 200、21,323 B）的图片文件名与内容：

- `20220124汉DM全侧a002Z1-红1分层ok.jpg`：**红色**汉 DM 全侧，5000×2998，实取 200、3,045,611 B；
- `汉EV双车.jpg`：汉 EV 双车，不是 DM-i；
- `20220322-汉dm-i-棕色皮椅002.jpg`、`20220125汉DMI大内饰a001.jpg`：内饰，不是外观；
- `发布会主题.jpg`：发布会主视觉，多车，不是单车商品图。

所以这张“最后的官方报道图”是**红色**，不是时光灰；只能作“2022 汉家族发布报道图（非官方、非本配置、非时光灰）”的临时占位，不能解决本车颜色。

### 8.5 明确不要再试的错路

- 2022 款汉 EV 创世版的时光灰图（56542/56566/56451）：前脸是封闭式 EV，不是 DM-i；
- 2023/2024/2025 款汉 DM-i：年款不对；
- 2022 款 DM-i 的尊荣型/尊享型/旗舰型：配置不对；
- 当前“汉DM-i智驾版”：代际/年款都不对；
- 把玄空黑图调色成时光灰：伪造，不做；
- 裁掉水印当自有图：侵权风险更高。

## 9. 最终建议

1. **这一台车（2022 款 121KM 尊贵型 时光灰）不要用汽车之家/太平洋汽车的图当商品主图。** 两张都是玄空黑，颜色不符；用了就要写“颜色不符”，那还不如不用。
2. **优先向车主拿实拍图**，走 `image_source_type=user_upload`，UI 标“图片来源：车主提供”（需先放开历史记录门禁，见 6.4）。这是唯一能同时满足年款、配置、颜色的方案。
3. **没有车主图就保持 `image=null` + `image_status=official_unavailable`**，前端“官方图待补”。不要为了填满卡片而放黑车图。
4. 如果运营坚持要占位：用汽车之家 A1（`https://car3.autoimg.cn/cardfs/product/g25/M08/07/32/autohomecar__ChwFj2KONaaAc5RUABHu_ICxmjI964.jpg`，200，678,106 B，3840×2880），标注“同款同配置、玄空黑、非时光灰、来源汽车之家（第三方，非官方）”；保留水印，收到通知即撤。
5. **不要做三站通用采集。** 懂车帝登录不可用，太平洋 503 不稳，汽车之家只能解决“年款+配置”而不能解决“颜色”；投入产出不成立。若将来要做，先做汽车之家单站，并把“目标颜色 0 张”作为硬失败。
