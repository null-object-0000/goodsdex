# 「发布时间」为什么没采到 + 替代方案（2026-10-17）

## 一、结论：**官方两个接口都不提供产品发布时间**（不是我们漏采）

实测：把两个采集源的全部原始响应（**10,492 条**）翻了一遍。

| 采集源 | 接口 | 用途 |
|---|---|---|
| `mi_cn_mobile` | `m.mi.com/mtop/xiaomishop/product/info` | 移动端商品详情 |
| `mi_cn_pc` | `api2.order.mi.com/product/view?product_id=` | PC 端（**参数表来自这里**） |

**这两个接口里的"时间"字段全都是「销售活动时间」，没有产品发布时间**：

```
on_sale_time        2026-10-12 10:00:00   ← 本次开售（营销活动）
sale_time / onSaleTimeTxt                 ← 同上
pre_start_time / final_start_time         ← 预售 / 尾款窗口
subscribe_end_time                        ← 预约提醒截止
modeStartTime / nowTime                   ← 销售模式开始 / 服务器时间
sale_mode_title     立即购买 / 订金预售 / 预约
```

**没有** `publishTime` / `releaseTime` / 发布 / 上市 / 发售 这类字段（两个源都没有）。
商品参数表里也只有 `加热方式 / 容量 / 适用人数 / 内胆材质 / 功能`。

## 二、但有替代线索：**图片 CDN 路径里带时间戳**

```
主图      pms_1634614406.66392610.jpg          → 1634614406 = 2021-10-19
详情图    202607031745_a0b11d95....jpg          → 2026-07-03 17:45
```

用「评价数」交叉验证（评价越多 = 卖得越久），**吻合度不错**：

| 型号 | 主图时间戳 | 详情图时间戳 | 评价数 | 判断 |
|---|---|---|---|---|
| 米家电饭煲 C1 | **2019-11-22** | ? | 5.6 万 | ✅ 最老 |
| 米家智能电饭煲 微压版 | **2021-10-19** | 2026-07-03 | 2.7 万 | ✅ 主图准；详情图是**后来换的图** |
| 米家智能小饭煲 2 | ? | 2022-05-20 | 1.5 万 | ✅ |
| 米家 IH 电饭煲 S1 | ? | 2024-09-24 | 9476 | ✅ |
| 米家 IH 电饭煲2 系列 | ? | **2026-03-16** | 3.2千↓ | ✅ 新品 |
| 米家智能 IH 电饭煲2 多功能版 | ? | **2026-09-14** | 58 | ✅ 最新 |

### 但要如实说清精度

- **主图时间戳 `pms_<10位>` ≈ 首次上架时间**（老品保留得好：C1 = 2019、微压版 = 2021）；
  但**很多商品换过主图，这个字段就没有**（表里一半是 `?`）。
- **详情图时间戳 = 图片最后更新日**（新品≈上市时间；**老品会被大促换图污染**，如微压版实际 2021 上市、详情图却是 2026-07-03）。

## 三、建议

1. **落一个 `estimated_release` 字段**：用「主图时间戳 + 详情图时间戳 + 评价数」三者交叉推断，
   **必须标注为"推断值、非官方"**，不能当事实用；
2. **要准确数据只能从外部补**：小米官网新闻稿 / 发布会信息 / 京东上架时间，或**人工维护**（和苹果线一样）；
3. **更重要的判断**：连"这台什么时候上市的"都只能推断 —— 说明**"折损判断"的数据基础很脆**。
   真正可靠的折损依据，只能靠**我们自己按小时积累的价格时间序列**（目前只有 7 天）。
   **越早开始攒，越早有依据。**
