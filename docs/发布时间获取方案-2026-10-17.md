# 如何拿到「发布时间/上架顺序」（2026-10-17 实测）

## 一、官方明确不提供「绝对发布时间」

三处都查过，全部没有：

| 位置 | 结论 |
|---|---|
| `m.mi.com/mtop/xiaomishop/product/info`（移动端详情） | 只有**销售活动时间**（开售/预售/尾款/预约），无发布/上市 |
| `api2.order.mi.com/product/view`（PC 详情） | 同上，无 |
| PC 商品页 HTML | 无 |
| `api2.order.mi.com/search/index`（搜索） | **有 `release_date` 字段，但全库填 0**（官方定义了不填） |
| 评论接口 `m.mi.com/mtop/xiaomishop/comment/list` | 接口**存在**，但返回 `sessionId is empty` → **需要登录态**；免登录路径全 404 |

**结论：绝对发布时间（年月日）拿不到。**

## 二、✅ 但拿到了官方的「上架顺序」—— `main_sort=4`

小米商城搜索接口的排序参数 `main_sort`：

```
GET https://api2.order.mi.com/search/index
    ?query=<关键词>&page_index=1&page_size=20
    &main_sort=4        ← 按上架时间倒序（新品优先）
    &filter_tag=0&sort_by=asc&callback=cb
```

**验证（手机类目，官方顺序）**：
```
REDMI Note 17 Pro 焕新版 → Xiaomi 18 Pro Max → 18 Pro → 18 Fold
→ K100 Pro Max → K90 至尊版 → Note 17 Pro → Note 17 → REDMI 17 5G
```
**单调新→旧，与产品线完全吻合** ✅

**用途**：可以落一个 **`release_rank`** 字段（相对顺序、客观、可复现），
解决"按发布时间排"的问题。**它不给绝对日期。**

## 三、绝对日期的两条路

| 路 | 精度 | 成本 | 风险 |
|---|---|---|---|
| **A. 登录抓评论**（最早评价时间 ≈ 上架时间） | 高 | 需小米账号扫码登录、维护 session | 账号风控、session 过期 |
| **B. CDN 图片时间戳推断** | 中（老品会被换图污染） | 零 | 无 |
| **C. 外部源/人工维护** | 高 | 费力、覆盖不全 | 无 |

**建议**：`release_rank`（官方顺序，可靠）+ B（推定日期，标注"非官方"）为主，
重点商品用 C 人工校准；A 仅在必要时启用。

## 四、顺带发现的其他时间线索（都可用作辅助）

```
主图      pms_1634614406.jpg        → 1634614406 = 2021-10-19（≈ 首次上架）
详情图    202607031745_xxx.jpg       → 2026-07-03（= 图片最后更新）
买家秀图  /a2/1790837951_xxx.jpg     → 评价时间（只能拿到最近 5 条）
```
