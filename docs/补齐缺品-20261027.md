## 请求纪律与保存

- 实际请求 **44 / 300**，全部为指定移动详情 POST：每个产品先不带 gid，再使用响应 `defaultGid` 请求，共 22 × 2。两次请求均保留证据；没有请求图片、PC 详情或搜索分页。
- 串行，并发 **1**；日志实测相邻请求“前一次结束 → 下一次开始”最短 **2.120132 秒**（≥2.1 秒）。HTTP 429 / `rate_limited` **0 次**，故本轮未发生实际退避；采集器对 429 使用 3、6 秒指数退避，重试也计入请求上限。
- 四个业务请求头及 Content-Type 沿用 [采集方法论](methodology.md) 与 `mi_cn.MTOP_HEADERS`，请求体 `[{}, {"productId": "<pid>"}]` / `[{}, {"productId": "<pid>", "gid": <defaultGid>}]`。
- 第 5、10、15、20 条及最终 22 条分别落盘；分类按 pid 仅插入不存在的项；档案仅增加不存在的 key，不更新旧价格、旧状态或次数，不将未见商品标为 missing。
- 分类映射：`supplement_categories` 对应 `宠物饮水机.json` / `键鼠套装.json`；枕头没有补充分类，回退 `tree_categories=枕头`。文件名经过既有 `pipeline.safe_filename`。

## 核验与复现

- 对运行前全部分类记录按原数组顺序逐条比较内容哈希，对全部档案旧 key 比较内容哈希：原记录、原价格、历史状态均未改变。发布集基线的每条记录也原样保留。
- 逐条核对响应 `productId`、goodsList 商品身份、官方名称、默认 gid、价格与首张轮播图；新增 pid 唯一，分类与档案均存在，发布图价与原响应相符。
- 专项离线测试覆盖本地重复不请求、明确下架不入库、容器/身份不匹配不借参数、配件分类、首图定位、旧分类/档案/发布价格保留，以及重复执行不重采不重复写入；发布格式原有测试通过（合计 3 项测试）。
- 复现入口：`python3 scripts/supplement_missing_products.py`。已有请求/结果可断点复用，重复执行本轮实测新增请求 0。
