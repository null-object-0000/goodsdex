# 数据获取方法总览（2026-10-30）

> 目的：把仓库里已经打过仗的方法汇总成一张可复用的表，并回答「哪个方法能搬到哪个品牌、补哪个具体缺口」。
>
> 边界：本轮只读已有文档与当前发布集，**没有重新调研、没有发新请求、没有写库、没有改脚本、没有推分支**。本文是唯一新增文件。
>
> 证据等级只用四种：**实测**（有 URL、状态码、字节数或可复核数据；含「实测负结果」）、**部分实测**（只验了样本/单条路径）、**推断**（由已有证据推出、未直接验证）、**缺口/未实测**（没有拿到或没有做）。没有实测的方法一律不写成已验证。

## 0. 结论先行

1. **有实测数据闭环的是 7 条产品线**：小米、Apple、大疆、富士、惠普、比亚迪、小米汽车。当前发布集共 3,794 行，品牌分布为小米 2,075、大疆 783、Apple 644、富士 63、惠普 218、比亚迪 8 个商品（38 个配置）、小米汽车 3 个商品（10 个配置）[M]。
2. **最大的缺口不是新品，是小米停售/旧款**：官方旧清单 1,443 个 pid 中已确认下架 1,361 个；当前发布集里 168 个停售型号有名字，但补名轮仍有 **1,195 个缺名**（补名轮口径；与全量 1,361 差 2 条，见 §5 #11）；170 条历史参考全部缺价、169 条缺图、77 条缺参数；全量 1,443 条里 **1,284 条没有已验证的官方规格页 URL** [S23][S24][S25][S26][M]。
3. **最可移植的不是某个站点的接口，而是三类方法**：①官方历史/支持目录（Apple Support、小米旧 sitemap）；②Wayback 归档 + 旧 CMS 资产编号/旧页 URL 探测（比亚迪汉 2022 已跑通，能救旧图、旧名）；③第三方参数/图库页（太平洋、汽车之家，只适合汽车的年款/配置/图，且带水印与版权风险）[S1][S14][S24][S12]。
4. **汽车当前款官方接口最完整，但年款和历史款官方不给**：比亚迪 8 个商品/38 个配置、小米汽车 3 个商品/10 个配置，价格和参数基本齐；年款只有 2026 款夏（官方名）和汉 2022（第三方 PCauto）两条，6/8 个比亚迪商品 `model_year=null`；小米汽车 3/3 全为 null [S11][S17][M]。
5. **索尼/佳能/尼康是空白，但空白原因不同**：索尼是「做了拿不到」——商城首页 200，WH-1000XM6 详情 403；佳能、尼康是「没做」——仓库里没有实测记录、没有采集器、没有文档，不能写成「官网没有数据」[S28]。
6. **别再试的路已经很清楚**：VECC 要 VIN+发动机号后 6 位+验证码；`app.miit.gov.cn` 两次超时；CPCA 7 次请求 5 次 403；汽车之家只有玄空黑且图片带水印；比亚迪 App 无整车模型、接口加密；懂车帝全站登录拦截；惠普支持站是 7 KB 空壳；按新 CDN 规律反推 2022 路径 57 条全 404 [S10][S12][S13][S8][S27]。

## 1. 方法总表

### 1.1 读表口径

- **计数单位不同，不能直接相加**：小米/Apple/大疆/富士/惠普是「商品行」；比亚迪/小米汽车是「商品（product）+ 配置（trim）」；停售款是「型号参考（model_reference）」。例如比亚迪旧文档的「33 条」是配置行，新结构是「7 个在售商品 + 1 个历史商品 = 8 个商品 / 38 个配置」，不能拿 33−8=25 当丢失 [S17][S18][S20]。
- **[M]** = 当前 data 分支 `public/meta.json`（`generated_at=2026-10-30T11:00:54Z`，count=3,794）与 `public/goods.json` 的只读统计；不是文档估算。
- **[S#]** = 来源编号，见文末「来源与复现」。
- **证据强度怎么读**：格子里有具体条数/URL/字段，且来源是实测文档或 `[M]` → **实测**；只验了样本/单条路径 → **部分实测**；写 `null`/`0`/「缺口」→ **缺口**；写「未核实/未验证/未实测」→ **未实测**；由已有证据外推但未直接验证 → **推断**。表格里没有标「推断/未实测」的计数，均来自实测文档或当前发布集。
- 表格里的「实测」只说明该方法在这个品牌上被实际跑通过，不说明全量覆盖；「缺口」只说明当前发布集/文档里没有，不说明官方一定没有。

## 2. 每个方法的可移植性

> 这一节按「方法」组织，每种方法都回答三件事：依赖什么前提、哪些品牌满足、搬过去能补哪个具体缺口（带预计条数）。预计条数一律给依据；没有实测的写「未实测」，不写成已验证。

### 2.1 方法 A：官方商城 SSR / 内嵌 JSON / JSON-LD

**依赖前提**：官网商品页服务端渲染，或页面内嵌 `window.__PRELOADED_STATE__`、`PRODUCT_SELECTION_BOOTSTRAP`、`setProduct({...})` 一类 JSON；有稳定的官方 ID（料号/商品号/配置 ID）；不需要登录。

**谁满足（实测）**：

- 惠普：类目页 `Product` JSON-LD + PDP `magentoStorefrontEvents.context.setProduct({...})` + `<dt>/<dd>` 规格表 [S8]。
- 大疆：商城详情 `window.__PRELOADED_STATE__.products.variants[]` + Product JSON-LD + 官网 specs `detailed-parameter-key/value` [S4]。
- Apple：购买页 `window.PRODUCT_SELECTION_BOOTSTRAP.productSelectionData` + `partNumber` [S1]。
- 小米：购买页 `api2.order.mi.com/product/view` + `buy_option`/`goods_list`；搜索 `search/index` JSONP [S3]。
- 富士：官方产品页 + Product JSON-LD（图 URL 来自商品页正文或 JSON-LD）[S6]。
- 比亚迪：`cms-api.byd.com` 免签名配置/价格/图接口；详细参数要官网访客短时签名 [S10]。
- 小米汽车：`website-api.xiaomiev.com` 参数对比 POST，免登录/免签名 [S10]。

**谁只满足一半**：索尼商城首页 200，有 `data-sku` 和价格容器，但 WH-1000XM6 详情 403，规格/售价/料号映射未确认 [S28]。佳能、尼康没有实测，不能判断 [S28]。

**搬过去能解决什么**：

|---|---|---|---:|---|
| 索尼/佳能/尼康从 0 到有 | 先对官方列表页做 Product JSON-LD + 商品卡 `data-sku` 侦察；不碰 403 详情 | 未知，不承诺 | 索尼首页有 `data-sku`/价格容器；详情 403 [S28] | 未实测 |

## 4. 缺口排序与建议

### 4.1 排序原则

1. **用户家里有的东西优先**：小米家电/手机、Apple 电脑/手机、相机、车。
2. **停售/停产款优先于长尾新品**：老物件才需要算日均；新品晚一点不影响。
3. **先身份后价格**：名字/型号都对不上，价格再多也没用。
4. **先官方后第三方**：官方图/价能上架；第三方图只能参考，还要过版权/门禁。
5. **按「能补多少条」而不是「技术多难」排**：1,195 条缺名 [S26] 比 1 条难搞的 App 车模更值得做。

- **工作量**：1–2 天（含抽样、限速、落盘、人工抽检）。
- **风险**：Wayback 429/TLS 断流；旧页可能只有壳没有标题；图片 CDN 失效；归档图不是「当前官方图」，必须标 `official_archive` + 快照日期。
- **验收**：30 条抽样中名字恢复率、图片 200/可解码率；每条保留 `source_url`、快照时间、SHA256；恢复不了的保持 null，不猜。

#### 建议 2：小米停售款「补价 + 补参数」——P0/P1，1 天

- **目标缺口**：170 条历史参考缺价；77 条有名停售款缺参数（全量 1,284 条没有已验证规格 URL）。
- **方法**：先跑旧导航 `api.order.mi.com/product/getTabInfo` 的 `last_known_price`（21/61 样本有 [S24]），只写 `last_known_price`，不写当前价；参数走官方旧规格页的 `p > b + span`/单表模板（29/61 样本成功 [S24]）。没有规格 URL 的，用 Wayback 旧规格页补 URL，仍拿不到就保持空。
- **预计条数**：价格上限 170；参数上限 77（有名记录），全量理论上限 1,284，但实际模板命中率未知。
- **工作量**：1 天（价格半天 + 参数半天）。
- **风险**：`last_known_price` 没有日期/不是最后成交价；旧规格页模板不匹配；同页多型号（电动牙刷主体/刷头）不能硬选。
- **验收**：每条价格带 `last_known_price_context`；参数逐对带来源 URL/请求编号；模板不匹配的记 `unsupported_or_empty_text_layout`，不编参数。

#### 建议 3：Apple「145 条图 + 295 条历史价」——P1，1–4 天

- **目标缺口**：93 条当前缺图 + 52 条历史缺图；295 条历史缺价；77 条历史缺年份。

- **预计条数**：图上限 145；历史价上限 295；年份上限 77。
- **工作量**：图 1 天；价 2–3 天（要逐条找发布稿）。
- **风险**：Apple 不一定公开人民币历史价；同系列图不能冒充某料号专属图；历史价不是当前价，不能进当前价序列。
