# 公开集补图片字段

验证日期：2026-10-23。本轮只修改导出链路，使用已有 `data/categories/*.json`，没有重抓商品数据、修改采集逻辑或频率，没有发布到 `data` 分支，没有 push。用户提供的丢图定位和线上数据数字作为已核事实使用，未重新调查。

## 变更与字段契约

- `src/goodsdex/publish.py::to_public()` 为每条记录新增顶层 `image`，直接取 `view.values.img_url`；缺失、空串或 null 输出 JSON `null`。
- 使用 `image`：原公开条目没有同名顶层字段，名称简短且表达主图用途。原有 `id/name/kind/category/price/market_price/gid/fetched_at/params` 和容器标记均保持不变。
- 不新增 `image_alt`，继续忽略整个 `carousel`、`pc_imgs` 等素材，避免放大公开集。不转换 URL 协议，不补取缺图。
- `_NOISE` 保留 `img_url` 用于防止它重复出现在 `params`；注释已明确它是顶层 `image` 的原始来源。模块说明及 `meta.json.note` 同步说明公开集包含主图链接，其他 meta 字段不变。
- 新增回归测试，覆盖主图提升、旧字段保留、素材数组不外泄，以及无图/空值不回退到轮播图。

## 发布后会发生什么

1. 人工确认发布后，新的全量导出将给每条商品增加 `image`（无图为 null），公开集只携带图片链接。已有字段不变，按现有字段读取且允许额外键的消费者保持兼容；严格拒绝未知键的 schema 需要先加可空字符串字段。
2. 用户已核实的服务端原样镜像会在后续成功同步新 `goods.json` 时带上该字段；若前端还未读取 `image`，单独更新数据不会自动显示图片。展示端应处理 null、图片加载失败与 HTTP 链接，并评估实际图片加载流量；不必为本次数据修复修改同步逻辑。
3. 本地同批快照 JSON 增大约 386 KB / 21.06%，全量同步的下载、缓存、存储相应增加；线上具体增量要在发布时重新测量。原本写死 1.9 MB 上限的下载/缓存配置需要检查。
4. 应在正式发布前通知下游维护者：新增 `image: string | null`、JSON 体积增长、图片按需加载及授权未确认的现状。通知是建议的后续动作，本轮没有代发消息。
5. 当前 `.github/workflows/crawl-all.yml` 会在全量任务中执行 `goodsdex.publish`，随后自动提交并 push `data` 分支。因此未来把本代码推到工作流使用的代码分支后，后续全量任务可能自动带出图片字段。价格刷新脚本只回灌已有条目的价格，不会主动为旧公开集补图，但会保留已存在的 `image`。本轮没有触发任何工作流，也没有更改它们；正式接入前应由人确认发布时间及自动任务安排。
