# 小米社区 / 大疆社区「个人主页设备列表」调研（2026-10-30）

> 实取时间：2026-10-30 23:06–23:13 CST。
> 范围：小米社区（`web.vip.miui.com` / `api.vip.miui.com`）、大疆社区（`bbs.dji.com`）的公开页面、公开接口、robots 与用户协议/隐私政策；不登录、不绕验证码、不伪造签名、不批量抓取他人资料。
> 边界：本轮只做调研并新建本文档；不写库、不改脚本、不推分支。
> 说明：本文只写实际取到的页面、接口返回与目视结果。拿不到的地方明确写“拿不到/未验证”，不写“应该有”。

## 0. 结论先行

1. **大疆社区有公开的「认证设备」列表，匿名可见，且能按昵称精确定位。** 个人主页 HTML 里直接有 `认证设备` 区块；普通账号的 Next.js 数据里 `initialDevices` 返回 11 件设备，粒度到套装全名（如“Mavic 3 Pro 畅飞套装（DJI RC Pro 遥控器）”）。没有购买时间/激活时间。
2. **小米社区没有公开的个人主页设备列表。** 公开主页接口 `api/community/user/home/page` 的 `entity` 里没有 `device/product` 字段；“我的设备”是登录后的本人页面，设备墙接口 `mtop/planet/vip/zeus/productWall/list` 未登录直接 **401**。
3. **小米公开主页唯一和“设备”有关的展示是发帖时的“机型”。** 隐私政策原文是“展示您的昵称、头像、机型与发布内容”，这是单条帖子的机型，不是“名下有哪些设备”的清单；个人简介字段只有 `signature`。
4. **大疆这条路技术上能走通，但合规上不能做。** 大疆《使用条款》明确禁止“任何自动的或非自动的‘抓取’行为”，并明确禁止“从本服务中收集或获得任何个人可识别信息，包括账号名称”。用户授权自己的账号，也不能覆盖这条平台禁止性约定。
5. **推荐替代：用户上传自己账号的「我的设备」截图，我们做 OCR + 人工确认。** 不碰账号密码、不碰 cookie、不后台抓取；论坛昵称自动导入这条产品路径应直接下掉。
6. **批量抓取他人资料一律不做。** 除了违反平台条款，还有账号封禁、PIPL 个人信息处理、反爬 WAF 等风险；本文不给“换姿势绕”的方案。

### 1.4 按昵称定位：精确昵称可直接打开主页

**URL：** <https://bbs.dji.com/home.php?mod=space&username=DJI+V-Master>

- HTTP：`200`
- 大小：`95,973 B`
- 标题：`个人主页 - 大疆社区`
- 页面同样是 `认证设备` 区块，5 个 `title` 与 `uid=1` 的列表一致
- URL 规律：`home.php?mod=space&username=<URL 编码后的昵称>`

结论：

- **只要昵称精确、账号存在，就能匿名定位到主页并看到设备**；不需要先知道 uid。
- 昵称里的空格会编码成 `+` 或 `%20`；中文昵称需要 URL 编码。
- 这不是“模糊搜索”，是精确用户名直达；模糊搜索接口本轮没有使用（`robots.txt` 禁止 `/search.php`、`/member.php`）。

### 1.5 公开主页 URL 规律

本轮实际见到的三种：

```text
https://bbs.dji.com/home.php?mod=space&uid=<uid>
https://bbs.dji.com/pro/user-center?mod=space&uid=<uid>&do=index
https://bbs.dji.com/home.php?mod=space&username=<昵称>
```

- 旧 `home.php?mod=space&uid=` 对普通账号会 `302` 到新 `/pro/user-center`；对 `uid=1` 仍直接 200。
- 个人主页里还出现短链 `http://bbs.dji.com/?1`（`?<uid>` 形式）。
- 新 `/pro/user-center` 是 Next.js SSR，`__NEXT_DATA__` 直接带 `initialDevices`，**不要求登录**。

### 1.6 可见性与隐私开关

- 普通账号接口返回 `home_page_accessible_by_self: true`、`home_page_accessible_by_others: true`。
- 这说明该主页对他人可见；接口用这个字段表达主页级可见性。设备列表是主页的一部分。
- **本轮没有在页面/接口里看到“设备列表单独设为好友可见/仅自己可见”的开关**；是否存在设备级开关，未验证。
- 页面还公开“已累计飞行 10000m”这类飞行距离；接口有 `hide_distance` 字段，说明距离可以隐藏，但**没有看到 `hide_devices` 一类字段**。

### 1.7 技术面

| 项 | 结果 |
|---|---|
| 是否纯前端渲染 | 旧主页是服务端渲染 HTML；新 `/pro/user-center` 是 Next.js SSR，设备在 `__NEXT_DATA__` |
| 是否需要浏览器执行 JS | 不需要。`curl` 直接拿到 HTML/JSON |
| 是否有公开 JSON 接口 | 主页本身是 HTML；新页内嵌 JSON。没有单独发现公开的“用户设备”JSON 端点 |
| 反爬 | 帖子内容页 `forum.php?mod=viewthread&tid=...` 返回 `200` 但是 **阿里云 WAF JS 挑战**（`aliyun_waf_aa`、`acw_sc__v2`），不是正文；个人主页本轮未触发 |
| 频率限制 | 本轮以 ≥2.3 秒间隔请求约 15 次，未遇到 429；未做压力测试，不能据此判断阈值 |
| robots | 见 3.2：禁止 `/search.php`、`/member.php`、`/home.php?mod=spacecp*`、`/api/` 等；**没有禁止 `home.php?mod=space&uid=` 这种公开主页** |

### 2.5 按昵称定位：搜索接口 401，主页只认 uid

**昵称搜索接口测试：**

```text
GET https://api.vip.miui.com/api/community/at/users/search?keyword=小米
HTTP/1.1 401 Unauthorized
Content-Length: 330

{"code":401,"loginUrl":"https://account.xiaomi.com/pass/serviceLogin?callback=...&sid=miui_vip"}
```

结论：

- 本轮测试的 `at/users/search` 是登录态接口，**未登录不能按昵称搜用户**；
- 公开主页 URL 的参数是 `uid` 或 `encryptUserId`，没有 `username`/`nickname` 参数；
- 因此**只知道昵称，无法稳定定位到小米社区用户**；如果用户给出主页链接里的 `uid`，公开主页能打开，但主页没有设备列表。


### 2.7 粒度与时间：未实测

因为设备墙接口 401，本轮**没有拿到真实设备列表响应**，所以不能确认：

- 是否只显示品类（“小米手机”）还是具体型号；
- 是否带绑定时间/购买时间；
- 是否显示数量（`count` 字段暗示可能有多台）。

前端代码只能证明它有 `name`、`imgUrl`、`count`、`category`、`productId` 这些字段；**不能把代码字段当成真实数据**。这一点在本文第 7 节明确列为“拿不到”。

## 3. 合规判断

> 以下是产品/工程判断，不是法律意见。真要上线，让法务复核。

### 3.1 大疆《使用条款》：明确禁止抓取与收集账号名称

来源：<https://www.dji.com/cn/terms?site=brandsite&from=footer>（HTTP `200`，`161,081 B`；页面标题“使用条款 - DJI 大疆创新”）

“使用限制”一节原文（逐条摘录）：

> 您保证在使用本服务的过程中，不参与如下禁止行为：

> 在任何媒介中复制、分发或披露本服务的任何部分，包括但不仅限于任何自动的或非自动的“抓取”行为；

> 使用包括但不仅限于“机器人”、“网页爬虫”、“离线阅读器”等在内的任何自动化系统访问本服务，且向大疆服务器发送超出一般人在相同时间段内使用常规的在线网络浏览器可能产生的数量的访问请求数量，除非大疆可撤销地许可某一公共搜索引擎运营商可以使用网络爬虫从 dji.com 上复制公众可获得的资料，但前提是该材料仅可用于创建公开可搜索索引，且不能被缓存或存档；

> 从本服务中收集或获得任何个人可识别信息，包括账号名称；

> 以非本服务提供或授权的任何技术或手段访问本服务的任何内容；或绕过我们可能用于阻止或限制对本服务的访问的措施，包括但不限于阻止或限制对任何内容进行使用或复制、对服务的使用或服务内容进行限制等的措施。

这四条叠在一起，结论很硬：

- **“自动抓取”被禁止，“非自动抓取”也被禁止**；
- **“收集或获得任何个人可识别信息，包括账号名称”被单独禁止**——昵称本身就在禁止范围内；
- **用户授权自己的账号，不能覆盖平台对“收集 PII”的禁止性约定**；用户同意的是“你读我的资料”，不是“平台允许你违反它的使用条款”；
- 唯一可能的例外是“大疆可撤销地许可的公共搜索引擎运营商”，且只能用于公开搜索索引、不能缓存/存档——我们不是搜索引擎，不适用。

### 3.2 大疆 robots.txt：没有禁止公开主页，但禁止搜索/会员/资料编辑接口

来源：<https://bbs.dji.com/robots.txt>（HTTP `200`，`534 B`）

原文关键行：

```text
User-agent: *
Disallow: /api/
Disallow: /data/
Disallow: /source/
Disallow: /install/
Disallow: /template/
Disallow: /config/
Disallow: /uc_client/

Disallow: /static/

Disallow: /api.php
```

要点：

- `robots.txt` **没有** Disallow `home.php?mod=space&uid=` / `username=` 这种公开主页；
- 但它 Disallow `/search.php`、`/member.php`、`/home.php?mod=spacecp*`、`/api/`；
- 所以“robots 允许抓公开主页”这个结论**不成立**：robots 只是没禁止这个路径，**使用条款单独禁止收集 PII**；
- 批量枚举 uid 会同时踩“抓取”“超量请求”“收集账号名称”三条。

### 3.3 小米：协议没有专门的“禁止抓取”条款，但设备墙本来就不公开

**用户协议：** <https://web.vip.miui.com/page/info/mio/mio/userProtocol?app_version=dev.21000>（HTTP `200`，`6,125 B`，SPA；正文在当前前端 chunk 内）

本轮全文检索结果：

- 没有发现“爬虫”“抓取”专门条款；
- 有通用的个人信息/隐私保护条款，例如第 5.2.3.3 条“发布、传送、传播、储存涉及他人隐私、个人信息或资料的内容”；
- 第 8.1 条约定，小米有权对违反法律法规或协议的行为采取删除信息、限制/中止/终止服务等措施；
- 协议没有给第三方“代用户读取账号数据”的授权。

**隐私政策：** <https://privacy.mi.com/xiaomicommunity/zh_CN/>（HTTP `200`，`33,948 B`；更新日期 2025-03-13）

关键原文：

> 当您在客户端编辑自己的个人主页时，我们会收集您设置的社区昵称、头像、性别、生日、地区与签名。

> 客户端内的服务模块可以绑定您的设备，以便针对设备提供对应的售后服务，绑定过程中我们需要获取您的设备SN码，用于展示设备信息，并在申请售后时，获取您的设备标识符（IMEI（Android Q以下版本）/OAID（Android Q及以上版本）），以提供售后服务。

要点：

- 隐私政策把“设备绑定”放在**售后服务**场景，不是“公开展示”；
- 个人主页收集项没有设备列表；
- 公开主页 API 也没有设备字段。

**robots：**

```text
GET https://web.vip.miui.com/robots.txt
HTTP/1.1 404 Not Found
Content-Length: 1025

GET https://api.vip.miui.com/robots.txt
HTTP/1.1 200 OK
Content-Length: 14
Content-Type: application/json

Crawl-delay: 3
```

要点：

- API robots 只给爬取延迟，没有 Disallow；
- 但“robots 没禁止”不等于“可以拿设备列表”：设备墙要登录，公开主页没有设备；
- 若真要做“用户授权自己的小米账号”，需要走小米账号 OAuth/开放平台；本轮**没有找到**面向普通用户的“读取自己米家设备列表”公开授权接口。

### 3.4 两种情况分开判断

| 场景 | 大疆 | 小米 | 判断 |
|---|---|---|---|
| **用户授权自己的账号**，我们自动读他的公开资料 | 即使有用户同意，仍违反《使用条款》的“禁止抓取/收集 PII（含账号名称）”；用户同意不能替代平台许可 | 公开主页没有设备列表；设备墙要登录。若让用户交 cookie/密码，属于账号凭据处理，风险更高 | **不做自动读取** |
| **用户自己截图**，我们 OCR 识别设备 | 截图由用户主动提供；我们不访问大疆服务；风险显著降低 | 同理，米家/小米社区“我的设备”截图由用户提供 | **可做，首选** |
| **批量抓取他人资料** | 明确违反使用条款；WAF/封号/民事风险 | 违反 PIPL 个人信息处理规则；无公开设备接口；封号风险 | **一律不做** |
| **找平台要官方 API/合作** | 唯一可能大规模合规的路径；需商务/法务谈 | 同理 | **长期选项，不是本轮方案** |

### 3.5 授权文案：截图路径要写，论坛抓取路径不要写

如果做截图 OCR，建议在入口处显式写：

> 请上传**你自己账号**的「我的设备」页面截图。我们只识别设备型号，用于生成待确认的物品清单；不会登录你的账号，也不会读取通讯录、位置或账号密码。截图会在识别完成后删除。请勿上传他人截图或包含身份证、SN 码、手机号等信息的图片。

如果是“填论坛昵称自动导入”，示例文案“确认这是你的账号，我们将读取你公开的设备列表”**也不要用**：

- 大疆条款禁止收集 PII（含账号名称），用户点“确认”不能使这个行为合规；
- 小米没有公开设备列表，填了也读不到；
- 这句文案会给用户“我们已获授权”的错觉，实际是把平台违规风险转嫁给用户。

### 3.6 结论

- **大疆：技术上可行，合规上不可行。** 不要做“输入昵称→后台抓主页→导入设备”。
- **小米：技术上也没有公开入口。** 不要做“输入昵称→读设备墙”。
- **唯一推荐的产品化路径：用户上传自己账号的截图，OCR + 人工确认。**

## 4. 替代路径对比

| 路径 | 能拿到什么 | 门槛 | 合规/账号风险 | 推荐度 |
|---|---|---|---|---|
| **A. 用户上传自己「我的设备」截图，OCR** | 型号/套装名，可能多件；取决于截图完整性 | 低：上传 + OCR + 勾选确认 | 低-中：用户主动提供；需告知、最小化、可删除；截掉昵称/头像/SN | **首选** |
| **B. 米家账号授权读取设备列表** | 若真有官方授权，可能拿到全量设备、房间、在线状态 | 高：需要 OAuth/开放平台；本轮**没有找到**面向普通用户的公开接口 | 高：若走非官方接口/让用户交密码，违反账号安全与隐私政策 | 不推荐（本轮不可行） |
| **C. 大疆 App / 账号接口** | 设备列表、飞行记录等 | 高：App-only/私有接口，可能要拆包、签名 | 高：违反大疆使用条款；拆包/逆向还有法律风险 | 不推荐 |
| **D. 用户手动录入/搜索型号** | 用户自己选的型号 | 低：搜索 + 选择 | 无平台风险 | 兜底 |
| **E. 官方合作/开放平台** | 取决于协议 | 很高：商务、法务、技术对接 | 低（在协议范围内） | 长期选项 |

### 4.1 A：截图 OCR（推荐）

适合的截图来源：

- 小米：米家 App「我的设备」页；小米社区 App「我的设备」页（如果用户能看到）。
- 大疆：DJI App 的设备页；大疆社区个人主页「认证设备」区块的截图。

流程：

1. 用户选平台（小米/大疆）；
2. 上传**自己账号**的截图；
3. 前端/后端裁掉头像、昵称、SN、手机号等无关信息（或提示用户先裁）；
4. OCR 提取型号/套装名；
5. 用型号库做归一化，给出候选；
6. 用户勾选/改数量/删除；
7. 写入“待确认物品”，不直接入库；
8. 识别完成后删除原图（或按隐私政策保留最短时间）。

优点：

- 不碰账号密码、cookie、验证码；
- 不触发大疆条款里“抓取/自动化访问”的那部分；仍要按个人信息保护做告知与最小化；
- 用户对自己的数据有控制感，失败可重试。

缺点：

- 依赖截图质量；套装名可能被截断；
- 需要型号库做归一化，否则 OCR 出来的是自由文本；
- 多件设备要用户确认，不能全自动。

### 4.2 B：米家账号授权（本轮不可行）

- 本轮没有找到“普通用户授权第三方读取自己米家设备列表”的公开 OAuth 接口；小米 IoT 开放平台主要面向设备厂商/开发者，不是这个场景。
- 如果让用户输入小米账号密码，或把 cookie 交给我们，属于高敏感凭据处理：账号安全、二次验证、封号、隐私合规都不可控。
- 即使有官方授权，也要看 scope 是否包含“设备列表”；本轮未验证到这样的 scope。

**判断：不推荐，不作为近期方案。**

### 4.3 C：大疆 App / 账号接口（不推荐）

- 大疆社区 Web 已经能匿名看到设备，不需要拆 App；但条款禁止抓取。
- 大疆 App 的设备列表接口是 App-only/私有接口，可能要签名、设备指纹、登录态；拆包/逆向成本高，且违反使用条款。
- 即使技术成功，也不能作为对外产品：平台随时可以封接口/封账号。

**判断：不做。**

### 4.4 D：手动录入/型号搜索（兜底）

- 对 OCR 识别失败的少数设备，提供“搜索型号”兜底；
- 不依赖任何平台接口，零合规风险；
- 缺点是费时，但比“导入失败/封号”好。

### 4.5 E：官方合作（长期）

- 如果这个功能是核心价值，正确路径是找小米/大疆谈官方 API 或数据合作；
- 在这之前，不要用抓取做 MVP。

## 5. 给产品的落地建议

1. **下掉“输入论坛昵称自动导入”**。大疆条款明确禁止；小米没有公开设备列表。这个功能既做不成，也会给平台合规埋雷。
2. **改成“上传截图 → OCR → 待确认列表”**。入口文案明确“只支持本人账号截图”。
3. **截图先裁剪/打码**：头像、昵称、SN、手机号、订单号都不要识别；只保留设备型号区域。
4. **OCR 结果必须用户确认**：型号归一化 + 数量 + 删除；不要直接写库。
5. **原图最短留存**：识别完成即删；如需保留排障，先征得用户同意并脱敏。
6. **不要保存论坛 uid/昵称/cookie**：截图路径不需要这些；保存只会扩大个人信息面。
7. **不要做后台轮询/批量任务**：哪怕用户给了主页 URL，也不要服务端去抓；这是条款红线。
8. **加指标**：OCR 识别率、用户改错率、每单耗时、放弃率；用数据决定是否值得做型号库。
