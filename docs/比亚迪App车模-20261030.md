# 比亚迪 App 车模与按配置/颜色取图调研（2026-10-30）

> 实取时间：2026-10-30 16:08–16:26 CST。
> 范围：比亚迪官方 Android App 的公开下载包、包内资源、Dart AOT 字符串、公开网关的未登录请求；不登录、不绕过风控、不伪造签名、不调用车控接口。
> 边界：本轮只新建本文档；APK 只落本地临时目录，分析完删除，不入 git、不提交任何仓库；证据只保留路径、字段名、状态码与图片 URL。
> 同 host 请求间隔 ≥2.1 秒（实测按 2.2 秒执行）。

## 0. 结论先行

1. **App 有「3D 车」能力，但没有随 APK 下发的整车 3D 模型，也没有按颜色命名的整车静态车模图。** 包内 `.glb/.gltf/.obj/.fbx` 数量均为 **0**；3D 车模是运行时按 `modelId`/`modelMD5`/`version` 动态下载的资源（`com.byd.aeri.car3d` + `dynamic_release_item(fileUrl,fileMD5,...)` + WebView/本地 AssetServer），不是开箱即用的图片。
2. **拿不到「2022 款 汉 DM-i 121KM 尊贵型 · 时光灰」那一张。** 服务端确实存在 `vehicleInfo/threeModelPicture/getModelPictureUrl`（还有 `getVehicleColorByVin`、`getAutoPicForInnerColor`、`getAutoModelPicUrlType45/Zero` 等配套接口名），但未登录裸请求只返回 `code=216` 的中文业务错误 + 172 字符 Base64 加密 `response`，没有图 URL；请求体还缺 App 侧的加密包装/有效车型参数，且成功路径至少还缺「2022 款的 `autoStyle`/车型包标识 + 时光灰 `color` 映射 + 有效 VIN」。
3. **合规风险高，不建议把 App 内车模渲染图当商品主图。** 这是 BYD 版权素材，App 内可用不等于允许外部商品页商用；加来源标注也不能消除著作权/商标/「官方背书」风险。实务上最多作**内部参考**；要用必须拿到 BYD 书面授权/数据合作，否则应保持 `image=null` / `official_unavailable`，优先车主授权实拍。

## 4. 不登录能不能取到图

### 4.1 分两层看

**第一层：图片 CDN 是否公开？**
是。`cache.bydauto.com.cn`、`www.byd.com/material/...` 上的官方图，直接 `curl` 就 200，不带 Cookie、不带 Referer、不带签名。见第 5 节。

**第二层：能不能拿到「这台车」的图 URL？**
不能。`getModelPictureUrl` 的未登录请求没有被网关 401 拦下，但它要 App 形状的请求；裸请求只拿到 `code=216` + 加密 `response`。DEX 里能看到网络加密相关模块/符号：

```text
com.byd.base.network.encrypt.*
NetworkEncryptModule
BangleCrypto
AESDecrypt
handleEncryptResponse
decryptResponseBody
decrypt content length is less than iv len.
Params / ParamsUtils
```

`assets/commonConfig.txt` 也是高熵加密文本，不是明文配置。能确认的是：

1. **响应被加密**：`response` 是 Base64，不是明文 JSON；
2. **请求不是普通 JSON 直传**：GET 带零散参数、POST 带 `{}`/假 VIN/猜测的 `autoStyle` 都停在 `216/271`；
3. **但不能确认 `271` 的唯一原因**：可能是缺少 App 加密包装，可能是参数不合法，也可能两者叠加。

除此之外，还缺：

- **VIN 或 `autoStyle` + 颜色映射**；
- **登录态/车辆绑定**（是否必需，本轮未验证）。

本轮没有解密、没有伪造请求，所以准确表述是：

> **不是「登录后才能取」，而是「未登录裸请求取不到」；登录后能否取、取到的是不是 2022 时光灰，本轮没有验证，也不写「应该有」。**

### 4.2 请求封装证据

- 本轮所有探针的错误响应 body 都是 251 B，`response` 固定 172 字符 Base64；明文只有 `code/message/status`。
- 字符串里出现 `AESDecrypt`、`decryptResponseBody`、`handleEncryptResponse`、`NetworkEncryptModule`、`BangleCrypto`。
- `assets/commonConfig.txt` 开头不是 JSON/XML，直接 `strings` 也读不出域名/路径。
- `assets/P_Public/setting.json` 只有 `{}`，不是配置入口。

这些证据足以支持「响应被加密、请求不是普通 JSON 直传」，但不足以支持「加密算法就是 AES-CBC/密钥是 xxx」，也不足以把 `271` 单独归因于加密——本轮不猜算法、不把推断写成结论。

## 6. 三条结论

### 6.1 有没有「按配置+颜色」的车模图？

**有工程能力，没有可直接取用的成品图。**

- 有：`car3d` 3D 渲染链路、`getModelPictureUrl` 服务端渲染图接口、`getVehicleColorByVin` 颜色查询、`getAutoModelPicUrlType45/Zero` 两种角度、`getCarModelColorPicUrl` 车型颜色图方法名。
- 没有：APK 内 0 个 `.glb/.gltf/.obj/.fbx`；没有按颜色命名的整车静态图；没有 2022 汉 DM-i 的模型包证据。
- 所以准确回答是：**App 里能按车型/颜色渲染 3D 车，但「2022 款 121KM 尊贵型 + 时光灰」的成品车模图，本轮没有拿到，也不能证明 App 内有。**

### 6.2 能不能拿到时光灰那台？

**不能。** 缺的不是「再试一个 URL」，而是三样硬东西：

1. **车型标识**：2022 款汉 DM-i 121KM 尊贵型对应的 `autoStyle` / `modelId` / 3D 模型包版本；
2. **颜色映射**：时光灰对应的 `colorId` / `configId` / `color` 值；
3. **请求封装**：App 的加密请求体 + 加密响应解密（或由已登录 App 自己发起）。

本轮只验证了接口存在和裸请求失败；没有 2022 车的 VIN，也没有解密请求，所以**没有图 URL、没有尺寸、没有白底/透明结论**。第 5 节的两张汉图是**当前智驾版**，不能冒充。

### 6.3 能不能合规用？

**风险高，不建议当商品图；最多内部参考。**

实务判断（不是法务意见）：

- **著作权**：3D 车模/官方渲染图是 BYD 的摄影/美术/模型作品，App 内展示许可是给用户看，不是给商家复制、裁剪、上架。
- **商标与背书**：车图本身带 BYD 车标/前脸设计，放到商品页会让买家以为「官方授权/官方图」，即使标「来源：比亚迪 App」也不能消除。
- **平台规则**：商品主图通常要求「实物拍摄/授权图」，官方渲染图容易被判定为盗图或虚假宣传。
- **标注来源不等于免责**：署名只解决「出处」问题，不解决「授权」问题。

分档建议：

| 用法 | 判断 |
|---|---|
| 商品主图/详情图直接使用 | **不要**；风险高 |
| 加「来源：比亚迪 App」后使用 | **仍不建议**；标注不取得授权 |
| 内部选型/比对/给运营看 | 可以，但不要对外发布、不要再分发 |
| 拿到 BYD 书面授权/数据合作后使用 | 可以，按授权范围标注 |
| 车主授权实拍 | 最优；仍建议保留授权凭证 |

## 7. 建议

1. **商品侧**：这台车继续 `image=null` / `image_status=official_unavailable`，前端显示「官方图待补」；不要用当前智驾版绿色图、ADAS 俯视图、底盘图充数。
2. **图源侧**：优先级仍是「车主授权实拍 > BYD 官方授权图 > 汽车之家同款同配置图（标注颜色差异）」。App 渲染图不进入商品图候选。
3. **如果一定要走 App 数据**：走正式数据合作/授权，拿接口文档、车型/颜色映射和商用许可；不要逆向加密、不要伪造签名、不要批量抓取。
4. **工程侧**：若未来拿到授权 URL，落库时至少记录 `source=official_app_render`、`license=authorized`、`model_id`、`color_code`、`angle`、`fetched_at`；没有 `license` 的 URL 一律不进商品图。
5. **本研究边界**：APK 已在分析后删除，未提交；本文只保留路径、字段、状态码、图片 URL 与尺寸，不保留 APK、不保留加密响应原文、不保留任何 token。
